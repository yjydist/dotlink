# manifest-schema Specification

## Purpose

定义 `dotlink.toml` 的定位, 字段与校验契约: 清单从哪里取, 哪些写法合法, 违反时如何整体拒绝并在任何文件系统改动之前结束.

## Requirements

### Requirement: 清单定位与仓库根 [V-1] [FR-015]

清单固定命名为 `dotlink.toml`, 从**当前工作目录**读取; 系统 MUST NOT 向上搜索父目录, 清单位置不可配置 (不提供指定清单位置或仓库根目录的参数或环境变量, 见 `cli-contract` 的"命令面固定为四个子命令且不接受操作性参数"). 清单文件所在目录即仓库根, 全部 `source` 相对路径以它为基准解析. 清单 MUST 存在且可读: 不存在, 无读取权限或其他读取失败 MUST 按清单校验失败整体拒绝, 退出码 2, 标准错误给出单行说明与底层原因, 且不改动文件系统.

#### Scenario: 在子目录中运行

- **WHEN** 用户在仓库的子目录中执行 `dotlink status`, 且该子目录没有 `dotlink.toml`
- **THEN** 该次调用按清单不存在处理, 退出码 2, 且不向上级目录查找

#### Scenario: 清单存在但不可读

- **WHEN** 当前目录存在 `dotlink.toml`, 但进程没有读取它的权限
- **THEN** 整体拒绝, 退出码 2, 标准错误只有一行"无法读取清单"说明并给出底层原因, 文件系统保持原样

#### Scenario: 当前工作目录不可用

- **WHEN** 当前工作目录已被删除, 进程无法确定自身位置
- **THEN** 按清单校验失败处理, 退出码 2, 说明指出"当前工作目录不可用"而不是"找不到清单"

### Requirement: 清单校验 V-2: TOML 语法合法

清单 MUST 能按 TOML 解析. 语法非法时整体拒绝, 且说明 MUST 同时给出出错位置与原因; 解析器不提供位置信息时 (当前依赖版本下不可构造的防御分支) 可退化为"位置未知", 但原因仍须给出.

#### Scenario: 语法错误报告行号

- **WHEN** 清单第 2 行把字符串值写成了裸标识符
- **THEN** 整体拒绝, 退出码 2, 说明包含"清单语法错误"与"第 2 行"

### Requirement: 清单校验 V-3: 条目数组非空

顶层 MUST 出现 `entry` 且为至少含一个元素的数组表 (`[[entry]]`). 缺失, 为空或写成 `[entry]` 表时整体拒绝.

#### Scenario: 只有注释的清单

- **WHEN** 清单不含任何 `[[entry]]`
- **THEN** 整体拒绝, 退出码 2, 说明指出至少需要一个条目

### Requirement: 清单校验 V-4: 字段必填且为非空字符串 [FR-001]

每个条目 MUST 同时提供非空的 `source` 与 `target` 字符串. 缺失, 为空或类型不符时整体拒绝, 且说明 MUST 指出条目下标.

#### Scenario: 第二个条目缺 target

- **WHEN** 第一个条目合法, 第二个条目缺少 `target`
- **THEN** 整体拒绝, 退出码 2, 说明包含 `entry[1]` 与 `target`

### Requirement: 清单校验 V-5: 目标路径唯一

系统 MUST 在规范化之后比较目标路径: 不存在两个条目声明同一个目标路径. 书写形态不同但规范化结果相同时同样拒绝, 说明 MUST 指出冲突的两个条目下标. 比较 MUST NOT 使用 `Path::canonicalize` -- 待部署的目标通常尚不存在. 两个目标路径都存在时, 判重 MUST 同时比较文件系统身份 (设备号与 inode): 不同写法指向同一对象时同样视为同一目标路径. 比较 MUST 同时使用词法规范化形态与解析末段符号链接后的比较形态; 两种形态任一重合 MUST 视为同一目标.

#### Scenario: 两种写法指向同一目标

- **WHEN** 两个条目分别写 `~/.bashrc` 与 `~/./.bashrc`
- **THEN** 整体拒绝, 退出码 2, 说明指出这两个条目

#### Scenario: 同一源配不同目标

- **WHEN** 两个条目使用同一个 `source`, 但 `target` 不同且互不包含
- **THEN** 清单被接受

#### Scenario: 大小写别名指向同一目标

- **WHEN** 在大小写不敏感的文件系统上, 两个条目分别把 `target` 写成既有文件 `~/.bashrc` 与 `~/.BASHRC`
- **THEN** 整体拒绝, 退出码 2, 说明指出这两个条目, 而不是让两条目先后操作同一个对象

#### Scenario: 符号链接目标与其 referent 同时出现

- **WHEN** 第一个条目的 `target` 是符号链接 `~/.config`, 第二个条目的 `target` 写成该链接解析后的同一目录
- **THEN** 整体拒绝, 退出码 2, 说明指出两个条目, 而不是把同一对象当成两个独立目标

### Requirement: 清单校验 V-6: 目标可解析且源限于仓库内 [FR-002]

每个 `target` MUST 可解析为绝对路径: `~/...` 与裸 `~` 展开为主目录, `~/` 之后多写的分隔符 (`~//.bashrc`) 同样按主目录展开, MUST NOT 被当作绝对路径; 绝对路径不拼接仓库根 (随后按路径规范化规则处理), 相对路径挂到仓库根. 其他以 `~` 开头的形态 (`~.bashrc`, `~foo/bar`) MUST 整体拒绝. 每个 `source` MUST 是仓库内的相对路径 (可指向文件或目录), 拒绝 `~` 前缀与绝对路径, 且解析并规范化后不得越出仓库根. 违反时说明 MUST 指出条目下标与书写形态; 源越界时同时给出越界结果.

#### Scenario: 漏写斜杠的主目录简写

- **WHEN** 某条目写 `target = "~.bashrc"`
- **THEN** 整体拒绝, 退出码 2, 说明指出该书写形态, 而不是在仓库内建出名为 `~.bashrc` 的路径

#### Scenario: 主目录简写后多写斜杠

- **WHEN** 某条目写 `target = "~//.bashrc"`
- **THEN** 目标解析为主目录下的 `.bashrc`, 而不是文件系统根下的 `.bashrc`

#### Scenario: 源经仓库内符号链接逃逸

- **WHEN** `source` 在仓库内, 但其祖先段是仓库内指向仓库外的符号链接
- **THEN** 整体拒绝, 退出码 2, 说明指出该条目与越界结果

#### Scenario: 仓库内的 .. 折叠回仓库内

- **WHEN** `source = "a/../b"` 且 `b` 仍在仓库内
- **THEN** 清单被接受, 源解析为仓库根下的 `b`

### Requirement: 主目录解析 [FR-013]

需要展开 `~` 时, `HOME` MUST 非空且为绝对路径; 缺失, 空值或相对值均属校验失败 (退出码 2, 零改动), 说明 MUST 指出 `HOME` 不可用的原因 (未设置或为空 / 不是绝对路径). 不含主目录简写的清单 MUST NOT 因 `HOME` 不可用而被拒.

#### Scenario: 相对 HOME

- **WHEN** `HOME` 被设为相对路径, 而清单中某条目使用 `~`
- **THEN** 整体拒绝, 退出码 2, 说明指出 `HOME` 必须是绝对路径

#### Scenario: 不用 ~ 的清单不受影响

- **WHEN** `HOME` 未设置, 但全部目标都是绝对路径
- **THEN** 清单被接受, 命令正常执行

### Requirement: 清单校验 V-7: on_conflict 取值受限

`on_conflict` 缺省为 `skip`; 出现时 MUST 恰为 `skip` 或 `replace_and_backup` 两个字面量之一. 其他取值 (含大小写不同的写法) 与非字符串整体拒绝; 说明 MUST 指出条目下标, 字符串非法值时给出该值, 非字符串时给出其 TOML 类型.

#### Scenario: 大小写不同的取值

- **WHEN** 某条目写 `on_conflict = "ReplaceAndBackup"`
- **THEN** 整体拒绝, 退出码 2, 说明包含 `entry[1]`, `on_conflict` 与该取值

### Requirement: 清单校验 V-8: 未知键整体拒绝

两个层级各自只有合法键: 顶层仅 `entry`, 条目内仅 `source` / `target` / `on_conflict`. 出现其他键时 MUST 拒绝整份清单, 说明指出键名与所在层级. 静默忽略不可接受, 因为拼错的键会退化成默认值, 让用户以为配置已生效.

#### Scenario: 拼错的键

- **WHEN** 某条目写 `onconflict = "replace_and_backup"`
- **THEN** 整体拒绝, 退出码 2, 说明包含 `entry[0]`, `onconflict` 与"条目内"

#### Scenario: 顶层多出的表

- **WHEN** 合法条目之外另有 `[foo]` 表
- **THEN** 整体拒绝, 说明包含 `foo` 与"顶层"

### Requirement: 清单校验 V-10: 目标不得自指

`target` 规范化后 MUST NOT 与本条目自己的 `source` 相同: 自指链接无法解析为一个存在的目标, 且 `replace_and_backup` 会先备份源文件, 再在原路径建立指向该路径自身的链接 (符号链接环), 使原路径不可用. 违反时说明 MUST 指出条目下标与书写形态. `target` 与 `source` 都存在时, 判等 MUST 同时比较文件系统身份 (设备号与 inode): 指向同一对象的两种写法同样视为自指. `source` 是符号链接时, 判等 MUST 同时比较 source 的 follow 身份与链接文本的解析目标; `target` 命中任一形态 MUST 视为自指.

#### Scenario: 两种写法归一化后重合

- **WHEN** 某条目写 `source = "shell/bashrc"` 与 `target = "shell/../shell/bashrc"`
- **THEN** 整体拒绝, 退出码 2, 说明指出自指

#### Scenario: 大小写别名形式的自指

- **WHEN** 在大小写不敏感的文件系统上, 某条目写 `source = "a"` 与 `target = "A"`, 两者是同一个文件
- **THEN** 整体拒绝, 退出码 2, 说明指出自指, 而不是备份源文件后建出自指链接

#### Scenario: 源符号链接指向目标

- **WHEN** 仓库内的 `source` 是一个符号链接, 其链接文本解析后等于该条目的 `target`, 或 `target` 位于其解析目标之内
- **THEN** 整体拒绝, 退出码 2, 说明指出源符号链接的解析目标与目标重叠, 而不是建立 `target -> source -> target` 的环

### Requirement: 清单校验 V-11: 源与目标路径隔离

目标之间 MUST NOT 互为祖先或后代, 比较 MUST 同时使用词法形态与解析末段符号链接后的比较形态. 目标自身的词法形态 MUST NOT 与任一源路径相同, 包含或被包含; 与源比较 MUST 同时使用源的词法形态与比较形态. 目标的比较形态 MUST NOT 与源比较: 正确部署的目标链接其比较形态就是源, 若把它视为重叠会使 apply 之后的清单失效; 该形态只参与目标之间的嵌套与 V-5. 多个独立目标仍可共享同一源. 参与比较的路径存在时, 判等与包含判定 MUST 同时比较文件系统身份 (设备号与 inode). `source` 是符号链接时, 其 follow 身份与链接文本的解析目标 MUST 同时参与与目标词法形态的比较.

#### Scenario: 目录目标下的子目标

- **WHEN** 一条部署整个目录, 另一条把目标写在该目录内部
- **THEN** 整体拒绝, 退出码 2, 说明指出相关条目与路径, 因为通过父链接可以修改源目录

#### Scenario: 目标覆盖另一条目的源

- **WHEN** 条目 A 的 `target` 等于条目 B 的 `source`
- **THEN** 整体拒绝, 退出码 2, 说明指出两个条目与重叠路径

#### Scenario: 目标包含本条目的源

- **WHEN** 某条目写 `source = "shell/bashrc"` 与 `target = "shell"`
- **THEN** 整体拒绝, 退出码 2, 说明指出该条目与重叠路径

#### Scenario: 别名形式的目录嵌套

- **WHEN** 一条部署整个仓库目录的别名写法, 另一条把目标写在仓库内部的子路径, 两条路径在文件系统上是同一个目录
- **THEN** 整体拒绝, 退出码 2, 说明指出相关条目与路径, 而不是放行后再通过父链接改写源目录

#### Scenario: 符号链接父目标下的子目标

- **WHEN** 第一个条目的 `target` 是符号链接 `~/.config`, 第二个条目的 `target` 是 `~/.config/nvim/init.lua`
- **THEN** 整体拒绝, 退出码 2, 零改动, 说明指出两个条目与命中的比较路径

#### Scenario: 源符号链接指向目标祖先

- **WHEN** 某条目的 `source` 是符号链接, 其解析目标包含另一个条目的 `target`, 或等于目标
- **THEN** 整体拒绝, 退出码 2, 零改动, 说明指出源符号链接的解析目标与目标重叠

### Requirement: 校验先于任何文件系统改动

整份清单的校验 MUST 在任何文件系统改动之前完成. 任一条规则不满足时退出码为 2 且 MUST NOT 产生任何改动, 包括不创建目录, 不建立链接, 不写备份.

#### Scenario: 校验失败时零改动

- **WHEN** 一份清单的最后一条含有未知键, 前几条本可正常部署
- **THEN** 四条命令都退出 2, 且目标路径, 父目录与备份目录均保持原样

### Requirement: 源条目存在性不属于清单缺陷

`source` 指向的文件或目录在仓库中不存在时, MUST NOT 视为清单校验失败. 该情形由条目的运行时状态 `SourceMissing` 表达, 只影响该条目, 不阻塞其余条目, 使用户可以先部署其余条目再补文件.

#### Scenario: 缺失的源不阻止其余条目

- **WHEN** 清单含有两条, 其中一条的源不存在
- **THEN** 清单被接受, 缺失的一条报告 `missing`, 另一条正常创建链接

### Requirement: 清单校验 V-9: 受保护落点

`target` 规范化后命中文件系统根 `/`, 当前用户主目录, 仓库根本身或其祖先 (如 `.` / `..`), 或清单文件自身 (仓库根下的 `dotlink.toml`) 时 MUST 整体拒绝, 说明 MUST 指出条目下标与书写形态. 这些落点一旦被替换备份, 毁掉的是整个文件系统, 整个主目录或源仓库; 替换清单文件自身会让后续命令失去唯一配置源. `~/sub` 与 `/etc/hosts` 这类合法落点不受影响.

#### Scenario: 裸 ~ 作为落点

- **WHEN** 某条目写 `target = "~"`
- **THEN** 整体拒绝, 退出码 2, 说明指出不能以主目录本身为落点

#### Scenario: 仓库根作为落点

- **WHEN** 某条目写 `target = "."` 或 `target = "sub/../.."`
- **THEN** 整体拒绝, 说明指出不能以源仓库为落点

#### Scenario: 清单文件自身作为落点

- **WHEN** 某条目写 `target = "dotlink.toml"` 或等价的绝对路径
- **THEN** 整体拒绝, 退出码 2, 说明指出不能以清单文件自身为落点

### Requirement: 清单校验 V-9a: 主目录落点的两种形态

主目录比较以 `HOME` 可解析为前提: `HOME` 缺失, 空值或为相对路径时无法确定主目录, 该项比较不适用, 清单 MUST NOT 因 `HOME` 不可用而被拒绝 (与"主目录解析"一致). 主目录的判别 MUST 同时覆盖 `HOME` 的书写形态与其解析末尾符号链接后的物理形态: `HOME` 自身可能是符号链接, 只比较其中一种形态会让写在另一种形态下的主目录落点漏过.

#### Scenario: 主目录路径本身是符号链接

- **WHEN** `HOME` 本身是一个符号链接, 而某条目把 `target` 写成该主目录解析符号链接后的物理路径
- **THEN** 整体拒绝, 退出码 2, 说明指出不能以主目录本身为落点

### Requirement: 清单校验 V-9b: 落点命中按文件系统身份判定

目标落点存在时, 命中判定 MUST 同时比较文件系统身份 (设备号与 inode): 与任一基准点指向同一对象的其它写法 (大小写别名, firmlink 别名) 同样命中. 身份读取不可用 (路径不存在或元数据读取失败) 时 MUST 退回规范化字符串比较, MUST NOT 因此拒绝清单. 基准点的身份 MUST 同时保存 lstat 形态与 follow 形态; 落点的 lstat 身份命中任一形态 MUST 视为同一对象.

#### Scenario: 大小写别名形式的仓库根

- **WHEN** 在大小写不敏感的文件系统上, 某条目把 `target` 写成仓库根路径的大小写变体
- **THEN** 整体拒绝, 退出码 2, 说明指出不能以源仓库为落点, 而不是当作普通目录备份后替换

#### Scenario: 别名形式的清单文件

- **WHEN** 某条目把 `target` 写成清单文件路径的另一种写法 (大小写变体或等价别名)
- **THEN** 整体拒绝, 退出码 2, 说明指出不能以清单文件自身为落点

#### Scenario: firmlink 别名形式的主目录

- **WHEN** 在 macOS 上, 某条目把 `target` 写成主目录的 firmlink 别名路径 (如 `/System/Volumes/Data/Users/<用户>`)
- **THEN** 整体拒绝, 退出码 2, 说明指出不能以主目录本身为落点

#### Scenario: 不存在的落点只做字符串比较

- **WHEN** 某条目的 `target` 不存在, 且其规范化字符串不等于任何基准路径
- **THEN** 清单被接受, 身份判等不可用不会使校验失败

#### Scenario: 主目录符号链接的 lstat 形态

- **WHEN** `HOME` 本身是符号链接, 某条目把 `target` 写成该符号链接路径的大小写变体或等价别名
- **THEN** 整体拒绝, 退出码 2, 说明指出不能以主目录本身为落点, 而不是因为 lstat 与 follow 身份不同而放行

### Requirement: 清单校验 V-12: 目标 basename 长度预算

`target` 解析后的末段 basename MUST 不超过 200 个字节; 超过时整体拒绝, 退出码 2, 且 MUST NOT 做任何文件系统改动. 预算为备份最终名, 备份暂存名, 恢复暂存名与 apply/undo 暂存名的固定后缀预留空间, 确保清单接受的每个目标都能被四条命令处理. 计数 MUST 使用路径的原始字节, MUST NOT 使用字符数或显示宽度. 说明 MUST 给出条目下标, 书写形态, 实际字节数与上限.

#### Scenario: 边界内的长 basename

- **WHEN** 某条目的 `target` 末段恰好 200 个 ASCII 字节, 其余字段合法
- **THEN** 清单被接受, 四命令可以正常处理该条目

#### Scenario: 超过预算的 ASCII basename

- **WHEN** 某条目的 `target` 末段为 201 个 ASCII 字节
- **THEN** 整体拒绝, 退出码 2, 零改动, 说明包含 201 与 200

#### Scenario: 多字节文件名按字节计数

- **WHEN** 某条目的 `target` 末段是 67 个 3 字节 UTF-8 字符 (共 201 字节), 显示宽度只有 134 列
- **THEN** 整体拒绝, 退出码 2, 说明按字节给出 201 与 200, 而不是按字符数放行

#### Scenario: 只创建链接的条目也受同一预算约束

- **WHEN** 某条目的目标当前不存在, `apply` 只会创建链接, 但 basename 为 201 字节
- **THEN** 仍在清单校验阶段拒绝, 退出码 2, 不因为本次动作不需要备份而放行

### Requirement: 目标完整路径长度预算 [V-13]

`target` 的规范化绝对路径字节数 (按 UTF-8) 加上工具可能追加的最长生成后缀 MUST 不超过平台路径预算. 最长生成后缀取备份最终名, 备份暂存名, 恢复暂存名, 替换暂存名与撤销暂存名中的最大者, 当前按 55 字节预留 (覆盖 7 位 pid, 2 位序号, `.partial` 与 `.dotlink-restore.partial` 等). 平台预算取自 `<limits.h>` 的 `PATH_MAX`: Linux 4096 字节, macOS 1024 字节. 超过时整体拒绝, 退出码 2, 零改动, 说明 MUST 给出条目下标, 书写形态, 解析后字节数与预算. 相对 `target` 按仓库根解析, 所以同一清单的接受面随仓库位置变化. 本预算的常量与 V-12 的 200 字节预算放在同一共享模块.

#### Scenario: 恰好预算接受

- **WHEN** 某条目的 `target` 规范化后字节数恰为 `PATH_MAX - 55`, 例如 Linux 上 4041 字节
- **THEN** 清单被接受, 四条命令按各自语义正常执行, 不在清单阶段报告路径长度

#### Scenario: 超出预算 1 字节拒绝

- **WHEN** 某条目的 `target` 规范化后字节数为 `PATH_MAX - 55 + 1`
- **THEN** 整体拒绝, 退出码 2, 零改动, 说明包含条目下标, 书写形态, 解析后字节数与预算

#### Scenario: 多字节路径按字节计

- **WHEN** 某条目的 `target` 由 3 字节 UTF-8 字符组成, 字符数看似未超预算但字节数超过 `PATH_MAX - 55`
- **THEN** 整体拒绝, 退出码 2, 说明按字节给出解析后长度, 不按字符数或显示宽度计算

#### Scenario: 相对 target 随仓库移动可能被拒

- **WHEN** 同一份含相对 `target` 的清单在较浅的仓库根下被接受, 随后仓库被移动到更深的目录使规范化绝对路径超过预算
- **THEN** 在新位置运行任一条命令都整体拒绝, 退出码 2, 说明给出解析后的绝对路径字节数

#### Scenario: 合法短路径不受影响

- **WHEN** 清单中的 `target` 规范化后远短于预算, 例如 `~/.bashrc`
- **THEN** 清单被接受, `apply` 与 `undo` 行为与既有规格一致, 不因 V-13 改变

### Requirement: 清单校验 V-9c: 主目录的祖先也是受保护落点

`target` 规范化后是 `HOME` 的祖先时 MUST 整体拒绝, 退出码 2 且零改动. 判别 MUST 同时覆盖 `HOME` 的书写形态与解析末段符号链接后的物理形态. 以 `~` 简写书写, 按路径组件词法折叠后经 `..` 离开主目录的落点 MUST 一并拒绝; 该词法判定 MUST NOT 解析祖先符号链接, 因此指向主目录外部的符号链接子目录不因本条被拒. `HOME` 不可用时该比较不适用, 清单 MUST NOT 因此被拒. 落点存在时 MUST 按文件系统身份判等, 取不到身份时退回规范化字符串比较. 说明 MUST 指出条目下标与书写形态.

#### Scenario: 主目录的父目录落点

- **WHEN** 仓库不在 `HOME` 之下, 某条目写 `target = "~/.."` (或等价的 `HOME` 父目录绝对路径)
- **THEN** 四条命令都以退出码 2 整体拒绝, 标准输出为空, 说明指出 `entry[0]` 与该书写形态, 且不创建链接或备份

#### Scenario: 经主目录上溯的子路径落点

- **WHEN** 仓库不在 `HOME` 之下, 某条目写 `target = "~//../x"`
- **THEN** 整体拒绝, 退出码 2, 说明指出条目下标与书写形态, 而不是把它当作主目录之下的普通目标

#### Scenario: 主目录物理形态的祖先

- **WHEN** `HOME` 本身是符号链接, 某条目把 `target` 写成其物理形态的祖先目录 (例如 `HOME=/home/u` 指向 `/mnt/u` 时的 `/mnt`)
- **THEN** 整体拒绝, 退出码 2, 说明指出不能以主目录的祖先为落点

#### Scenario: 祖先目录的大小写别名

- **WHEN** 在大小写不敏感的文件系统上, 某条目把 `target` 写成 `HOME` 某个祖先目录的大小写变体, 二者文件系统身份相同
- **THEN** 整体拒绝, 退出码 2, 说明指出不能以主目录的祖先为落点, 而不是当作普通目录备份后替换

#### Scenario: 合法的下级与绝对落点不受影响

- **WHEN** 某条目写 `target = "~/sub"` 或 `target = "/etc/hosts"`
- **THEN** 清单被接受, 命令正常执行, 不会被 V-9c 误伤

#### Scenario: HOME 缺失时绝对落点不被误拒

- **WHEN** `HOME` 未设置, 清单中的目标全部是绝对路径且不是任何可判定主目录的祖先
- **THEN** 清单被接受, 该比较不适用不会使校验失败

### Requirement: 清单校验 V-14: 运行期 NAME_MAX 预算

清单校验 MUST 在静态 basename 与完整路径预算之后, 对每个 `target` 从解析后的路径向上寻找最近的已存在祖先. 若该祖先可读且 `statvfs` 成功, 系统 MUST 读取 `f_namemax`; 当 `target` 末段字节数加最长生成名后缀超过 `f_namemax` 时 MUST 整体拒绝, 说明给出条目下标, 实际字节数, 生成名预算与文件系统上限. 找不到已存在祖先或 `statvfs` 失败时 MUST 跳过该检查, 仍使用静态预算; MUST NOT 因此拒绝清单. PATH_MAX 继续使用平台常量, 本要求不增加运行期 PATH_MAX 探测.

#### Scenario: 常见文件系统接受 200 字节末段

- **WHEN** `f_namemax` 为 255, `target` 末段为 200 字节, 最长生成名后缀为 50 字节
- **THEN** 清单被接受, 四条命令可继续

#### Scenario: 较小 NAME_MAX 在清单层拒绝

- **WHEN** 最近已存在祖先的 `f_namemax` 为 143, `target` 末段为 200 字节
- **THEN** 整体拒绝, 退出码 2, 说明包含条目下标与 143, 不创建任何链接或备份

#### Scenario: 探测失败时不误拒

- **WHEN** 最近的已存在祖先不可读, 或 `statvfs` 调用失败
- **THEN** 跳过运行期 NAME_MAX 检查, 清单仍按静态预算判定
