# manifest-schema Specification

## Purpose

定义 `dotlink.toml` 的定位, 字段与校验契约: 清单从哪里取, 哪些写法合法, 违反时如何整体拒绝并在任何文件系统改动之前结束.

## Requirements

### Requirement: 清单定位与仓库根 [V-1] [FR-015]

清单固定命名为 `dotlink.toml`, 从**当前工作目录**读取; 系统 MUST NOT 向上搜索父目录, 清单位置不可配置 (不提供指定清单位置或仓库根目录的参数或环境变量, 见 `cli-contract` 的"命令面固定为四个子命令且不接受操作性参数"). 清单文件所在目录即仓库根, 全部 `source` 相对路径以它为基准解析. 清单 MUST 存在且可读: 不存在, 无读取权限或其他读取失败 MUST 按清单校验失败整体拒绝, 退出码 2, 标准错误给出单行说明与底层原因, 且不改动文件系统.

#### Scenario: 在子目录中运行

- **WHEN** 用户在仓库的子目录中执行 `dotlink status`, 且该子目录没有 `dotlink.toml`
- **THEN** 该次调用按清单不存在处理, 退出码 2, 且不向上级目录查找

#### Scenario: 清单存在但不可读

- **WHEN** 当前目录存在 `dotlink.toml`, 但进程没有读取它的权限
- **THEN** 整体拒绝, 退出码 2, 标准错误只有一行"无法读取清单"说明并给出底层原因, 文件系统保持原样

#### Scenario: 当前工作目录不可用

- **WHEN** 当前工作目录已被删除, 进程无法确定自身位置
- **THEN** 按清单校验失败处理, 退出码 2, 说明指出"当前工作目录不可用"而不是"找不到清单"

### Requirement: 清单校验 V-2: TOML 语法合法

清单 MUST 能按 TOML 解析. 语法非法时整体拒绝, 且说明 MUST 同时给出出错位置与原因; 解析器不提供位置信息时 (当前依赖版本下不可构造的防御分支) 可退化为"位置未知", 但原因仍须给出.

#### Scenario: 语法错误报告行号

- **WHEN** 清单第 2 行把字符串值写成了裸标识符
- **THEN** 整体拒绝, 退出码 2, 说明包含"清单语法错误"与"第 2 行"

### Requirement: 清单校验 V-3: 条目数组非空

顶层 MUST 出现 `entry` 且为至少含一个元素的数组表 (`[[entry]]`). 缺失, 为空或写成 `[entry]` 表时整体拒绝.

#### Scenario: 只有注释的清单

- **WHEN** 清单不含任何 `[[entry]]`
- **THEN** 整体拒绝, 退出码 2, 说明指出至少需要一个条目

### Requirement: 清单校验 V-4: 字段必填且为非空字符串 [FR-001]

每个条目 MUST 同时提供非空的 `source` 与 `target` 字符串. 缺失, 为空或类型不符时整体拒绝, 且说明 MUST 指出条目下标.

#### Scenario: 第二个条目缺 target

- **WHEN** 第一个条目合法, 第二个条目缺少 `target`
- **THEN** 整体拒绝, 退出码 2, 说明包含 `entry[1]` 与 `target`

### Requirement: 清单校验 V-5: 目标路径唯一

系统 MUST 在规范化之后比较目标路径: 不存在两个条目声明同一个目标路径. 书写形态不同但规范化结果相同时同样拒绝, 说明 MUST 指出冲突的两个条目下标. 比较 MUST NOT 使用 `Path::canonicalize` -- 待部署的目标通常尚不存在.

#### Scenario: 两种写法指向同一目标

- **WHEN** 两个条目分别写 `~/.bashrc` 与 `~/./.bashrc`
- **THEN** 整体拒绝, 退出码 2, 说明指出这两个条目

#### Scenario: 同一源配不同目标

- **WHEN** 两个条目使用同一个 `source`, 但 `target` 不同且互不包含
- **THEN** 清单被接受

### Requirement: 清单校验 V-6: 目标可解析且源限于仓库内 [FR-002]

每个 `target` MUST 可解析为绝对路径: `~/...` 与裸 `~` 展开为主目录, `~/` 之后多写的分隔符 (`~//.bashrc`) 同样按主目录展开, MUST NOT 被当作绝对路径; 绝对路径不拼接仓库根 (随后按路径规范化规则处理), 相对路径挂到仓库根. 其他以 `~` 开头的形态 (`~.bashrc`, `~foo/bar`) MUST 整体拒绝. 每个 `source` MUST 是仓库内的相对路径 (可指向文件或目录), 拒绝 `~` 前缀与绝对路径, 且解析并规范化后不得越出仓库根. 违反时说明 MUST 指出条目下标与书写形态; 源越界时同时给出越界结果.

#### Scenario: 漏写斜杠的主目录简写

- **WHEN** 某条目写 `target = "~.bashrc"`
- **THEN** 整体拒绝, 退出码 2, 说明指出该书写形态, 而不是在仓库内建出名为 `~.bashrc` 的路径

#### Scenario: 主目录简写后多写斜杠

- **WHEN** 某条目写 `target = "~//.bashrc"`
- **THEN** 目标解析为主目录下的 `.bashrc`, 而不是文件系统根下的 `.bashrc`

#### Scenario: 源经仓库内符号链接逃逸

- **WHEN** `source` 在仓库内, 但其祖先段是仓库内指向仓库外的符号链接
- **THEN** 整体拒绝, 退出码 2, 说明指出该条目与越界结果

#### Scenario: 仓库内的 .. 折叠回仓库内

- **WHEN** `source = "a/../b"` 且 `b` 仍在仓库内
- **THEN** 清单被接受, 源解析为仓库根下的 `b`

### Requirement: 主目录解析 [FR-013]

需要展开 `~` 时, `HOME` MUST 非空且为绝对路径; 缺失, 空值或相对值均属校验失败 (退出码 2, 零改动), 说明 MUST 指出 `HOME` 不可用的原因 (未设置或为空 / 不是绝对路径). 不含主目录简写的清单 MUST NOT 因 `HOME` 不可用而被拒.

#### Scenario: 相对 HOME

- **WHEN** `HOME` 被设为相对路径, 而清单中某条目使用 `~`
- **THEN** 整体拒绝, 退出码 2, 说明指出 `HOME` 必须是绝对路径

#### Scenario: 不用 ~ 的清单不受影响

- **WHEN** `HOME` 未设置, 但全部目标都是绝对路径
- **THEN** 清单被接受, 命令正常执行

### Requirement: 清单校验 V-7: on_conflict 取值受限

`on_conflict` 缺省为 `skip`; 出现时 MUST 恰为 `skip` 或 `replace_and_backup` 两个字面量之一. 其他取值 (含大小写不同的写法) 与非字符串整体拒绝; 说明 MUST 指出条目下标, 字符串非法值时给出该值, 非字符串时给出其 TOML 类型.

#### Scenario: 大小写不同的取值

- **WHEN** 某条目写 `on_conflict = "ReplaceAndBackup"`
- **THEN** 整体拒绝, 退出码 2, 说明包含 `entry[1]`, `on_conflict` 与该取值

### Requirement: 清单校验 V-8: 未知键整体拒绝

两个层级各自只有合法键: 顶层仅 `entry`, 条目内仅 `source` / `target` / `on_conflict`. 出现其他键时 MUST 拒绝整份清单, 说明指出键名与所在层级. 静默忽略不可接受, 因为拼错的键会退化成默认值, 让用户以为配置已生效.

#### Scenario: 拼错的键

- **WHEN** 某条目写 `onconflict = "replace_and_backup"`
- **THEN** 整体拒绝, 退出码 2, 说明包含 `entry[0]`, `onconflict` 与"条目内"

#### Scenario: 顶层多出的表

- **WHEN** 合法条目之外另有 `[foo]` 表
- **THEN** 整体拒绝, 说明包含 `foo` 与"顶层"

### Requirement: 清单校验 V-9: 目标落点不得退化

`target` 规范化后命中文件系统根 `/`, 当前用户主目录, 仓库根本身或其祖先 (如 `.` / `..`), 或清单文件自身 (仓库根下的 `dotlink.toml`) 时 MUST 整体拒绝, 说明 MUST 指出条目下标与书写形态. 这些落点一旦被替换备份, 毁掉的是整个文件系统, 整个主目录或源仓库; 替换清单文件自身会让后续命令失去唯一配置源. `~/sub` 与 `/etc/hosts` 这类合法落点不受影响. 主目录比较以 `HOME` 可解析为前提: `HOME` 缺失, 空值或为相对路径时无法确定主目录, 该项比较不适用, 清单 MUST NOT 因 `HOME` 不可用而被拒绝 (与"主目录解析"一致). 主目录的判别 MUST 同时覆盖 `HOME` 的书写形态与其解析末尾符号链接后的物理形态: `HOME` 自身可能是符号链接, 只比较其中一种形态会让写在另一种形态下的主目录落点漏过.

#### Scenario: 裸 ~ 作为落点

- **WHEN** 某条目写 `target = "~"`
- **THEN** 整体拒绝, 退出码 2, 说明指出不能以主目录本身为落点

#### Scenario: 主目录路径本身是符号链接

- **WHEN** `HOME` 本身是一个符号链接, 而某条目把 `target` 写成该主目录解析符号链接后的物理路径
- **THEN** 整体拒绝, 退出码 2, 说明指出不能以主目录本身为落点

#### Scenario: 仓库根作为落点

- **WHEN** 某条目写 `target = "."` 或 `target = "sub/../.."`
- **THEN** 整体拒绝, 说明指出不能以源仓库为落点

#### Scenario: 清单文件自身作为落点

- **WHEN** 某条目写 `target = "dotlink.toml"` 或等价的绝对路径
- **THEN** 整体拒绝, 退出码 2, 说明指出不能以清单文件自身为落点

### Requirement: 清单校验 V-10: 目标不得自指

`target` 规范化后 MUST NOT 与本条目自己的 `source` 相同: 自指链接无法解析为一个存在的目标, 且 `replace_and_backup` 会先备份源文件, 再在原路径建立指向该路径自身的链接 (符号链接环), 使原路径不可用. 违反时说明 MUST 指出条目下标与书写形态.

#### Scenario: 两种写法归一化后重合

- **WHEN** 某条目写 `source = "shell/bashrc"` 与 `target = "shell/../shell/bashrc"`
- **THEN** 整体拒绝, 退出码 2, 说明指出自指

### Requirement: 清单校验 V-11: 源与目标路径隔离

目标之间 MUST NOT 互为祖先或后代; 任一目标 MUST NOT 与任一源路径相同, 包含或被包含. 比较以规范化后的路径组件为准, 多个独立目标仍可共享同一源. 违反时四条命令都在改动前拒绝.

#### Scenario: 目录目标下的子目标

- **WHEN** 一条部署整个目录, 另一条把目标写在该目录内部
- **THEN** 整体拒绝, 退出码 2, 说明指出相关条目与路径, 因为通过父链接可以修改源目录

#### Scenario: 目标覆盖另一条目的源

- **WHEN** 条目 A 的 `target` 等于条目 B 的 `source`
- **THEN** 整体拒绝, 退出码 2, 说明指出两个条目与重叠路径

#### Scenario: 目标包含本条目的源

- **WHEN** 某条目写 `source = "shell/bashrc"` 与 `target = "shell"`
- **THEN** 整体拒绝, 退出码 2, 说明指出该条目与重叠路径

### Requirement: 校验先于任何文件系统改动

整份清单的校验 MUST 在任何文件系统改动之前完成. 任一条规则不满足时退出码为 2 且 MUST NOT 产生任何改动, 包括不创建目录, 不建立链接, 不写备份.

#### Scenario: 校验失败时零改动

- **WHEN** 一份清单的最后一条含有未知键, 前几条本可正常部署
- **THEN** 四条命令都退出 2, 且目标路径, 父目录与备份目录均保持原样

### Requirement: 源条目存在性不属于清单缺陷

`source` 指向的文件或目录在仓库中不存在时, MUST NOT 视为清单校验失败. 该情形由条目的运行时状态 `SourceMissing` 表达, 只影响该条目, 不阻塞其余条目, 使用户可以先部署其余条目再补文件.

#### Scenario: 缺失的源不阻止其余条目

- **WHEN** 清单含有两条, 其中一条的源不存在
- **THEN** 清单被接受, 缺失的一条报告 `missing`, 另一条正常创建链接
