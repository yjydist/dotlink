# path-normalization Specification

## Purpose

定义路径规范化与符号链接解析的语义: 系统如何在不要求路径存在的前提下, 把两种书写形态归一到同一个字符串, 从而判定"链接是否指向预期位置"与"链接是否由本工具创建".

## Requirements

### Requirement: 规范化不要求路径存在 [R2]

系统 MUST 提供一种非严格 realpath 语义的路径规范化: 对已存在的段解析符号链接, 对不存在的尾段只做词法规整 (逐段消除 `.` 与 `..`), 不对整个路径做存在性要求. 相对路径没有已知的物理前缀, 因此只做词法规整, 不解析符号链接段; 生产调用点全部传入绝对路径. 该函数 MUST NOT 用 `Path::canonicalize` 实现 -- 后者在路径任一段不存在时返回错误, 会把悬空链接降级处理.

#### Scenario: 悬空链接仍能被规范化

- **WHEN** 待规范化的路径尾部指向一个不存在的文件
- **THEN** 规范化仍返回一个确定的结果, 而不是错误

#### Scenario: 规范化是幂等的

- **WHEN** 同一路径 (其符号链接链长度不超过深度上限) 被连续规范化两次
- **THEN** 第二次的结果与第一次相同

#### Scenario: 相对路径只做词法规整

- **WHEN** 相对路径 `alias/rc` 的第一段在当前目录下是一个已存在的符号链接
- **THEN** 结果仍是按词法整理的相对路径, 该链接段不被解析

### Requirement: 已存在的祖先段解析符号链接

路径中已存在的段若是符号链接, 系统 MUST 读取其文本并按链接所在目录继续解析, 直到得到非链接的已存在段. 这是让别名形态与物理形态落到同一字符串的唯一方式: macOS 上 `/tmp` 是 `/private/tmp` 的符号链接, 而链接文本可能写成别名形态, 另一侧由内核给出的当前目录是物理形态.

#### Scenario: 别名形态与物理形态归一

- **WHEN** 一条链接的文本经别名形态 (`/tmp/...`) 书写, 仓库根经内核解析为物理形态 (`/private/tmp/...`)
- **THEN** 两侧规范化到同一路径, 该链接被判为指向正确

#### Scenario: 相对链接文本以链接所在目录为基准

- **WHEN** 中间某段是指向 `../real` 的相对符号链接
- **THEN** 规范化按链接所在目录解析该文本, 得到物理路径

### Requirement: 末段永不解析

路径的最后一个组件 MUST NOT 被解析为符号链接, 即使它本身是符号链接. 路径的身份是链接自身所在的位置, 而不是它指向的目标; 穿透末段会让判定目标路径时直接看到源文件, 使"未部署", "指向错误", "别人的链接"三种状态塌缩成"目标被普通文件占用", 也使撤销再也找不到要移除的那个链接.

#### Scenario: 目标路径本身是链接

- **WHEN** 待规范化的路径末段是一个已存在的符号链接
- **THEN** 结果仍是该链接自身所在的位置

#### Scenario: 祖先段经别名抵达时的末段

- **WHEN** 路径的祖先段是符号链接, 末段也是符号链接
- **THEN** 祖先段被解析, 末段被保留

### Requirement: 缺失尾段只做词法处理

一旦某段不存在, 尚未消去的缺失尾段 MUST NOT 再访问文件系统, 只做词法规整. 若 `..` 消去了全部缺失段并退回已解析祖先, 后续祖先段 MUST 恢复物理解析.

#### Scenario: 缺失段被 .. 完全消去

- **WHEN** 路径形如 `missing/../alias/rc`, 其中 `alias` 是已存在的符号链接
- **THEN** 规范化得到 `alias` 目标下的 `rc`, 而不是保留 `missing` 前缀

#### Scenario: 缺失段未被消去

- **WHEN** 路径形如 `missing/alias/rc`, 且 `missing` 不存在
- **THEN** 结果按词法保留该形态, 不解析 `alias`

### Requirement: 根与前导父目录的边界

绝对路径的根前缀 MUST 被保留, `..` 上溯到根后 MUST NOT 再回退. 相对路径开头的 `..` MUST 被保留, 且不得被后续的 `..` 抵消.

#### Scenario: 上溯超过根

- **WHEN** 输入是 `/a/../../b`
- **THEN** 结果为 `/b`

#### Scenario: 相对路径的前导 ..

- **WHEN** 输入是 `../../a` 与 `a/../../b`
- **THEN** 结果分别为 `../../a` 与 `../b`

### Requirement: 符号链接环有界

解析符号链接时 MUST NOT 无限递归: 链接链 (含环) 超过固定层数后停止解析并退化为词法处理, 使自指链接与互指链接都能在有限时间内返回结果.

#### Scenario: 自指链接

- **WHEN** 某段是指向自身的符号链接, 其后还有子路径
- **THEN** 规范化在有限时间内返回, 结果是该段下的子路径, 而不是崩溃或无响应

#### Scenario: 两节点互指

- **WHEN** 两个符号链接互相指向
- **THEN** 规范化同样在有限时间内返回

### Requirement: 归属判定与相等判定共用同一规范化 [R2] [FR-012]

"链接是否指向预期位置"与"链接是否由本工具创建"两项判定 MUST 基于同一个规范化函数, 且 MUST 覆盖三处输入: 链接文本解析后的绝对路径, 仓库根, 以及解析阶段产出的源路径. 只规范化其中一侧会使比较落在两套路径语义上.

#### Scenario: 仓库根含 .. 段

- **WHEN** 仓库根以 `<dir>/repo/../repo` 形态传入, 而链接文本使用规范化后的源路径
- **THEN** 该链接仍被判为指向正确

#### Scenario: 源路径在解析阶段即被规范化

- **WHEN** 检查条目的解析结果
- **THEN** 源路径与目标路径都已是规范化后的绝对路径, 而不是字面拼接结果

#### Scenario: 链接文本含 .. 段

- **WHEN** 目标路径上的链接文本写成 `<仓库>/alias/../shell/bashrc`, 而本条目的源是 `<仓库>/shell/bashrc`
- **THEN** 该链接被判为指向正确 (`status` 报 `ok`), 而不是 `wrong` 或 `foreign`

### Requirement: 指向仓库内但已失效的链接仍归本工具

链接文本落在仓库根之内时, 即使其指向的目标已不存在, 系统 MUST 判定该链接由本工具创建. 悬空链接在 dotfile 场景中很常见 (源文件被重命名或删除, 旧链接仍在主目录), 若判为"别人的链接", 撤销将拒绝清理本工具自己的产物, 只剩用户手工删除才能收拾. 本条目的源也缺失时, 状态判定按 `entry-classification` 的求值顺序先给出"源缺失", 该组合不属于本要求及其 Scenario 覆盖的情形.

#### Scenario: 仓库内的悬空链接

- **WHEN** 目标路径上的链接文本指向仓库内一个已被删除的文件, 且该文件不是本条目的 `source`
- **THEN** 该链接被归为"本工具创建但指向错误", 撤销会移除它

#### Scenario: 仓库外的悬空链接

- **WHEN** 目标路径上的链接文本指向仓库外一个不存在的文件
- **THEN** 该链接被归为"别人的链接", 撤销不触碰它
