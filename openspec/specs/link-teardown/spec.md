# link-teardown Specification

## Purpose

定义撤销侧的语义: `undo` 如何只清理本工具创建的链接, 在存在备份时恢复原内容, 并在任何冲突或失败下保证不删除不属于本工具的数据. 备份的命名, 查找与保留由 `backup-lifecycle` 约束, 其中"撤销前的备份快照在动手之前确定"与"目录读取失败不是没有备份"也归该能力; 本能力只定义撤销分支与恢复结果.

## Requirements

### Requirement: 只移除本工具创建的链接 [FR-009] [FR-010]

`undo` MUST 只移除判定为"已是最新"或"指向错误"的目标路径, 因为这两种状态都蕴含链接落在仓库根之内, 即本工具的产物. 其他状态 MUST NOT 触碰目标路径, 尤其"别人的链接"可能正是用户自己的配置.

#### Scenario: 本工具的链接被移除

- **WHEN** 目标路径是指向仓库内的链接, 执行 `undo`
- **THEN** 链接被移除, 该行 token 为 `undo` 或 `restore`

#### Scenario: 别人的链接被跳过

- **WHEN** 目标路径是指向仓库外的链接, 执行 `undo`
- **THEN** 该行 token 为 `skip`, 链接保持原样, 退出码 1

#### Scenario: 真实文件不被删除

- **WHEN** 目标路径上是一个普通文件或目录
- **THEN** 其中的数据保持不变, 该行 token 为 `skip`

### Requirement: 撤销的 token 由状态与备份有无共同决定

`undo` 的 token MUST 按状态与"同目录是否存在完整命名的备份"取定, 与"是否允许移除"无关: 已是最新或指向错误且有备份 -> `restore`; 已是最新或指向错误且无备份 -> `undo`; 目标为空且有完整备份 -> `restore`; 目标为空且无完整备份 -> `ok`; 目标被别的链接, 文件或目录占用 -> `skip`; 源缺失 -> `missing`; 无法判定或执行失败 -> `fail`. 目标为空时的 `restore` MUST NOT 先移除任何对象, MUST 在恢复落位时拒绝覆盖期间新建的内容. `Absent` MUST NOT 归为 `skip`. 恢复后目标被恢复内容占用: 若恢复内容不是本工具创建的链接, 再次 `undo` MUST 报告 `skip`; 若恢复内容本身是仓库根内的链接, 再次 `undo` MUST 按同一归属规则报告 `restore`; 两种情形都 MUST NOT 改变目标内容, MUST NOT 删除备份.

#### Scenario: 无备份的撤销

- **WHEN** 目标路径是本工具的链接, 同目录没有备份
- **THEN** token 为 `undo`, 计入成功列

#### Scenario: 有备份的撤销

- **WHEN** 目标路径是本工具的链接, 同目录有一份完整备份
- **THEN** token 为 `restore`, 说明给出备份路径

#### Scenario: 未部署不得归为跳过

- **WHEN** 目标路径本就不存在, 且同目录没有完整备份
- **THEN** token 为 `ok`, 计入已是最新列

#### Scenario: 目标为空但有备份

- **WHEN** 目标路径本就不存在, 同目录有一份完整备份
- **THEN** token 为 `restore`, 备份内容被恢复到目标路径, 说明给出备份路径, 退出码按现有两条件判据给出

#### Scenario: 目标为空恢复后再次撤销

- **WHEN** 第一次 `undo` 在目标为空时恢复了备份, 恢复内容不是本工具创建的链接
- **THEN** 第二次 `undo` 报告 `skip`, 目标内容与备份保持不变, 退出码 1

### Requirement: 撤销只恢复用户原始备份

`undo` 的备份查找与恢复 MUST 只使用用户备份命名空间 `<原名>.dotlink-backup.` 中完整命名的备份. 自愈备份 (`<原名>.dotlink-heal.<时间戳>` 及其消歧形态) MUST NOT 被 `undo` 选中, MUST NOT 被恢复, MUST NOT 被删除或改写. 因此自愈后撤销回到自愈前的状态: 目标原本不存在时只移除链接; 目标原本是用户内容且其备份仍在时恢复该用户备份. 自愈备份继续留在磁盘上, 由用户自行清理. 本要求只约束可用于恢复的备份集合, token 与退出码映射仍由既有 requirement 决定.

#### Scenario: 自愈后撤销回到未部署态

- **WHEN** 目标路径是自愈产生的指向当前 `source` 的链接, 同目录只有该次自愈留下的 `.dotlink-heal.` 备份
- **THEN** `undo` 移除链接, 不恢复自愈备份, 自愈备份的路径与内容保持不变, 该行 token 为 `undo`

#### Scenario: 用户备份优先于自愈备份

- **WHEN** 同目录既有更早的用户备份 `<原名>.dotlink-backup.<时间戳>`, 又有自愈产生的 `.dotlink-heal.` 备份, 目标路径是自愈后的链接
- **THEN** `undo` 恢复用户备份, 自愈备份保持原样, 该行 token 为 `restore`

#### Scenario: 自愈备份不被消费

- **WHEN** 一次撤销在只有 `.dotlink-heal.` 备份的目标上移除了链接
- **THEN** 自愈备份仍在原路径且内容不变, 可再次检查而不会被第二次撤销删除

### Requirement: 撤销幂等且退出码随备份情形而异

`undo` MUST 是幂等的: 重复运行 MUST NOT 改变目标路径的内容, MUST NOT 删除非本工具内容. 未恢复备份时第二次运行全部为 `ok` 并退出 0; 恢复出的原内容若不是指向仓库内的链接, 第二次运行把它判为占用并报告 `skip`, 退出 1; 若恢复出的原内容本身是指向仓库内的链接, 它按同一归属规则重新归类, 因而不报 `skip` -- 有备份时再次恢复同一份内容, token 为 `restore`, 退出 1.

#### Scenario: 目标为空时再次撤销

- **WHEN** 第一次撤销移除了链接且没有备份可恢复, 第二次执行 `undo`
- **THEN** 全部为 `ok`, 退出码 0, 无任何改动

#### Scenario: 恢复过备份后再次撤销

- **WHEN** 第一次撤销恢复了备份, 且恢复出的原内容不是指向仓库内的链接
- **THEN** 第二次执行 `undo` 把它报告为跳过, 不被删除或再次消费, 退出码 1

#### Scenario: 恢复出的内容本身是仓库内的链接

- **WHEN** 第一次撤销恢复的备份本身是指向仓库内的链接, 第二次执行 `undo`
- **THEN** 该链接按同一归属规则重新判定, 报告 `restore` 并退出码 1, 目标路径的内容保持不变, 备份仍在原地

### Requirement: 动手前复核目标仍是符号链接

判定与动手之间目标路径可能被替换, 因此移除或恢复之前 MUST 以原子不覆盖的 rename 把目标移入同目录暂存名, 再复核暂存对象. 暂存对象不是符号链接时 MUST 把它移回原路径 (若原路径为空), MUST 保留该路径, MUST NOT 消费备份, 并在说明中指出"判定之后被替换". 复核 MUST 同时确认暂存符号链接的目标仍属于本工具 (等于本条目的 `source` 或落在仓库根内); 暂存链接的目标落在仓库外时 MUST NOT 删除, 而是移回原路径并报告失败. 恢复的前提是本次运行亲手移除了该路径上的符号链接.

#### Scenario: 链接被换成真实文件

- **WHEN** 判定时目标路径是本工具的链接, 执行前被替换成用户自己的文件, 且同目录有备份
- **THEN** 该文件被保留, 备份不被恢复, 该行报告失败或跳过并给出原因

#### Scenario: 动手前复核身份

- **WHEN** 撤销准备移除目标路径时发现它已不是符号链接
- **THEN** 拒绝移除, 保留该路径, 说明指出"判定之后被替换"

#### Scenario: 链接被换成仓库外链接

- **WHEN** 判定时目标路径是本工具的链接, 执行前被替换成指向仓库外的链接
- **THEN** 该链接被移回原路径并保留, 不被删除, 该行报告失败

### Requirement: 恢复失败时链接原样保留以便重试

移除链接并恢复备份时, 系统 MUST 先把链接原子移到同目录暂存名, 再复制备份就位. 复制失败且原路径仍为空时 MUST 把链接移回, 使该条目可在下一次 `undo` 重试. 回滚冲突时 MUST 保留暂存链接并在说明中给出其完整路径, MUST NOT 为恢复原状而覆盖期间新建的内容.

移除暂存链接失败时 MUST 先尝试以原子不覆盖的 rename 把链接移回原路径, 使下一次 `undo` 可重试; 移回成功时 MUST 报告失败并说明链接已回到原路径. 移回失败时 MUST 保留暂存链接, MUST NOT 删除它, 并在说明中同时给出移除失败原因与暂存链接的完整路径.

恢复失败说明 MUST 给出所尝试的备份路径与失败原因. 恢复成功但清理暂存链接失败时 MUST NOT 静默: MUST 保留恢复出的内容, 在说明中给出残留暂存链接的完整路径, 并把该条目报告为失败.

#### Scenario: 备份不可读

- **WHEN** 备份文件不可读, 复制到暂存名失败
- **THEN** 链接回到原路径, 该行报告失败, 说明给出所尝试的备份路径与失败原因, 下次运行仍可重试

#### Scenario: 回滚时原路径被占用

- **WHEN** 恢复失败, 回滚前原路径已被新内容占用
- **THEN** 新内容保持原样, 链接留在暂存名, 说明同时给出恢复原因, 回滚原因与暂存路径

#### Scenario: 移除链接失败时先移回

- **WHEN** 暂存并复核通过后, 移除暂存链接失败, 且原路径仍为空
- **THEN** 链接被 rename 回原路径并保留, 该行报告失败, 下一次 `undo` 仍可重试

#### Scenario: 移除失败且移回失败

- **WHEN** 移除暂存链接失败, 且原路径已被新内容占用
- **THEN** 新内容保持原样, 链接留在暂存名, 说明同时给出移除失败原因与暂存链接的完整路径

#### Scenario: 恢复成功但清理暂存链接失败

- **WHEN** 备份已恢复到目标路径, 但清理暂存链接失败
- **THEN** 恢复出的内容保持原样, 该行报告失败, 说明给出残留暂存链接的完整路径

### Requirement: 暂存名不得覆盖任何既有对象

撤销过程中的暂存名 MUST 以原子不覆盖的方式取得; 名称已被占用时 (包括被悬空链接, 目录或普通文件占用) MUST 追加递增序号重试, MUST NOT 覆盖或合并既有对象. 恢复落位同样 MUST 拒绝覆盖期间新建的内容. 恢复落位使用排他取得的中间名 `<目标路径>.<pid>.dotlink-restore.partial`; 该名被占用时在 `.dotlink-restore.partial` 之前插入递增序号重试 (`<目标路径>.<pid>.<序号>.dotlink-restore.partial`), 中间名只用于写入, MUST NOT 参与任何备份查找. 平台不支持不覆盖移动时 MUST 直接报告失败, MUST NOT 退回可覆盖的改名.

#### Scenario: 撤销暂存名被占用

- **WHEN** 首次尝试的暂存名上已有用户文件
- **THEN** 使用下一个序号, 用户文件保持不变

#### Scenario: 恢复落位被占用

- **WHEN** 复制备份成功, 但原路径在复制期间被新建内容占用
- **THEN** 恢复被拒绝, 占用物与备份副本均不被覆盖

### Requirement: 备份文件恢复后仍留在原地

恢复成功后 MUST NOT 删除本次恢复的备份文件本身. 更早备份的使用与保留, 以及"系统不提供备份回收"的边界, 见 `backup-lifecycle` 的"取最新按时间戳再按序号数值"与"备份不被自动回收"; 本要求只约束撤销侧的"恢复不消费备份"这一结果.

#### Scenario: 恢复后备份仍在

- **WHEN** 一次撤销成功恢复了备份
- **THEN** 备份文件的路径与内容保持不变

#### Scenario: 多份备份只消费最新一份

- **WHEN** 同目录存在两份完整备份
- **THEN** 只恢复最新的一份, 另一份保持原样
