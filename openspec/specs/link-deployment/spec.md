# link-deployment Specification

## Purpose

定义部署侧的语义: `preview` 与 `apply` 如何消费同一份判定结果, 在目标路径上建立链接并在必要时先备份, 以及失败与冲突时如何保证不丢失已有内容.

## Requirements

### Requirement: 部署按判定结果建立链接 [FR-003]

`apply` MUST 逐条目执行判定导出的动作, 在目标路径建立指向前述源条目的符号链接. 执行层 MUST NOT 自行重新判定; 它只执行已经给出的动作.

#### Scenario: 未部署的条目被创建

- **WHEN** 源存在, 目标路径不存在, 执行 `apply`
- **THEN** 目标路径成为一个指向源的符号链接, 该行 token 为 `create`

#### Scenario: 已是最新的条目不动

- **WHEN** 目标已是指向源的链接, 执行 `apply`
- **THEN** 该行 token 为 `ok`, 目标路径的元数据不变

### Requirement: 自动创建缺失的父目录 [FR-005]

目标路径的各级父目录不存在时, `apply` MUST 自动创建它们. `preview` MUST NOT 创建任何目录.

#### Scenario: 多级父目录

- **WHEN** 目标为 `~/.config/nvim/init.lua` 且 `~/.config` 不存在, 执行 `apply`
- **THEN** 缺失的各级目录被创建, 链接建立成功

#### Scenario: 预览不建目录

- **WHEN** 同一情形下执行 `preview`
- **THEN** 输出报告将创建链接, 但文件系统上不出现任何新目录

### Requirement: 部署是幂等的 [FR-004]

对同一清单与同一文件系统状态重复执行 `apply` MUST NOT 产生额外改动, MUST NOT 报错, 且 MUST 如实报告条目已处于期望状态. 无副作用的动作 (已是最新, 报告源缺失, 报告无法判定, 拒绝冲突) MUST NOT 触碰任何路径, 包括不创建缺失的父目录.

#### Scenario: 连续两次部署

- **WHEN** 一份清单连续执行两次 `apply`
- **THEN** 第二次全部为 `ok`, 退出码 0, 目标路径的元数据与之前相同

#### Scenario: 无副作用的动作不创建路径

- **WHEN** 执行层收到一个无副作用的动作 (已是最新 / 报告源缺失 / 报告无法判定 / 拒绝冲突)
- **THEN** 该动作不创建任何路径 (含缺失的父目录), 目标路径也保持原样; 该执行层不变量由直接构造动作的单元测试锁定, 不依赖某个在真实判定中恰好可达的组合

### Requirement: 单条目失败不中断其余条目 [FR-014]

单个条目的操作失败时 MUST 继续处理其余条目, 在结束时给出完整的逐条结果, 并以退出码 1 结束. 失败行 MUST 附带原因.

#### Scenario: 一个条目失败, 其余成功

- **WHEN** 三个条目中第二个因权限不足无法建立链接
- **THEN** 第一与第三条正常完成, 第二条报告失败, 退出码 1

### Requirement: 预览与执行使用同一判定 [FR-006]

`preview` MUST 完全只读, 且其结论 MUST 与随后 `apply` 的实际行为一致: 预览报告将创建或替换的, `apply` 会执行对应动作; 预览报告冲突的不会被执行. 该一致性指状态与动作结论, 而不是动作的执行结果: 动作在执行期失败时 `apply` 报 `fail` 并保留原状, 这一情形不属于不一致; 其他不一致 MUST 只可能来自两次判定之间文件系统的外部变化. 预览行给出的预测备份名按预览时刻算出的时间戳生成, 跨秒时与随后实际使用的名字可能不同, 只要命名规则相同即满足本要求.

#### Scenario: 预览与实际行为一致

- **WHEN** 在不修改文件系统的前提下, 对同一份清单先 `preview` 再 `apply`
- **THEN** 两次输出的 token 序列相同

#### Scenario: 预览报告预测的备份名

- **WHEN** 某条目将被备份后替换, `preview` 报告备份
- **THEN** 该行给出的备份路径按当前实况算出, 与随后执行使用的命名规则相同 (跨过秒级时间戳边界时字面值可以不同, 不要求与实际名逐字相同)

### Requirement: 预览行同时给出当前状态与将执行的动作

`preview` 的每条目行 MUST 先给出该条目的当前状态, 并在该条目需要动作时给出将执行的动作; 不需要动作时 MUST NOT 报告动作. 当前状态与动作 MUST 来自同一次判定, 使用户能在执行前逐行核对"现状 + 将发生什么".

#### Scenario: 未部署的条目

- **WHEN** 某条目未部署
- **THEN** 该行同时包含"未部署"与"将创建链接"

#### Scenario: 已是最新的条目不报告动作

- **WHEN** 某条目已是指向源的链接
- **THEN** 该行只报告"已是最新", 不出现"将"字样的动作说明

### Requirement: 目录源建立整目录链接 [FR-018]

源是目录时, `apply` MUST 建立指向该目录本身的整目录符号链接, MUST NOT 对其内容逐个建链. 该行为不要求输出中出现文件或目录的类型标签.

#### Scenario: 目录条目

- **WHEN** 源是一个含若干文件的目录, 目标路径不存在, 执行 `apply`
- **THEN** 目标是单一符号链接, 指向该目录, 目标下的子文件通过链接可见

### Requirement: 未获许可的冲突保持原样 [FR-007]

目标被非本工具创建的内容占用, 且该条目未声明覆盖许可时, `apply` MUST 保持占用物原样, 报告冲突与原因, 并使退出码为 1. 系统 MUST NOT 提供命令行级的全局覆盖开关: 覆盖许可只有条目级声明这一个来源.

#### Scenario: 默认拒绝覆盖

- **WHEN** 目标路径上是用户自己的普通文件, 条目使用默认策略
- **THEN** 文件内容不变, 该行 token 为 `conflict`, 退出码 1

#### Scenario: 无全局开关

- **WHEN** 用户尝试用参数强制覆盖
- **THEN** 该参数不被接受, 调用以退出码 2 失败

### Requirement: 本工具的错误链接在部署时自愈

`apply` MUST 把 "指向错误" 视为本工具创建的链接, 无论 `on_conflict` 取值都替换为指向当前 `source` 的正确链接. 替换前 MUST 备份旧链接本身 (不跟随其目标), 备份命名沿用既有规则. 该行 MUST 报告 `replace` 并给出备份路径. `preview` MUST 报告同一动作与预测备份路径, 且不修改文件系统. `undo` 的语义不变.

#### Scenario: source 改名后 apply 自愈

- **WHEN** 目标路径是本工具创建的链接, 指向仓库内旧路径, 而清单的 `source` 已改为新路径, 且该条目使用默认 `on_conflict`
- **THEN** `apply` 成功, 旧链接被备份, 目标成为指向新 `source` 的链接, 该行 token 为 `replace`, 退出码按整体结果计算

#### Scenario: preview 预测自愈

- **WHEN** 同一状态执行 `preview`
- **THEN** 该行 token 为 `replace`, 说明给出预测备份路径, 且 `preview` 不修改文件系统

### Requirement: 获许可的替换先完成备份再删除原对象 [FR-008]

条目声明 `replace_and_backup` 时, `apply` MUST 先把现有对象完整备份, 备份落定之后再删除原对象并建立链接. 顺序 MUST NOT 颠倒: 原对象是唯一副本, 先删除再复制会让一次中途失败变成不可恢复的数据丢失. 备份失败时 MUST NOT 删除原对象.

#### Scenario: 备份失败时原对象保留

- **WHEN** 备份目录内容时中途失败
- **THEN** 原对象及其内容保持原样, 该条目报告失败, 不出现最终名的备份

#### Scenario: 备份成功但替换失败

- **WHEN** 备份已完成, 删除原对象或建立链接失败
- **THEN** 失败说明给出备份文件的完整路径, 使用户能找回原内容

### Requirement: 替换的目标可能是任何对象类型

替换 MUST 按对象类型正确处理: 普通文件复制其内容, 目录递归备份其子树, 符号链接备份链接本身而不跟随. 删除符号链接时 MUST 只移除链接本身, 不删除其指向的内容.

#### Scenario: 替换别人的符号链接

- **WHEN** 目标路径是指向仓库外的符号链接, 且条目允许覆盖
- **THEN** 备份是一个保留原链接文本的符号链接, 原链接指向的内容未被删除或复制
