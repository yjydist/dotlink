# Design

## Context

`src/backup.rs:378-401` 的 `timestamp()` 调用 `OffsetDateTime::now_local()`, 失败时由 `timestamp_at(Option<OffsetDateTime>)` 退化到 `now_utc()`. `src/backup.rs:111-147` 的 `scan_backups` 把每个候选名拆成 `(时间戳, 序号, 文件名)`, 再用 `src/backup.rs:442-446` 的 `cmp_backup_key` 选出最大者, 其中第一步是比较时间戳字符串. `src/lib.rs:273-338` 的 `undo` 在动手之前用 `find_latest` 取快照, 这份快照决定实际恢复哪份内容.

退化是进程级且静默的: 同一个目标可能先后留下 `TZ=Asia/Shanghai` 的本地时间戳, `TZ=UTC` 或时区不可用时的 UTC 时间戳, 以及夏令时回拨造成的重复本地时间戳. 这些字面值不在同一时间轴上, 字符串比较反映的是偏移差而不是时间差. `src/backup.rs:380` 的注释声称 "退化只影响时间戳的字面值, 不影响任何不变量", 与排序实际依赖时间戳可比较这一事实矛盾.

`time` 的 `local-offset` feature 目前只有一个使用点 (`now_local()`); 它按平台可选启用 `libc` 与 `num_threads`. 命名形态, 同秒消歧序号, 查找规则与 "备份不自动回收" 由 `backup-lifecycle` 固定, 本次只改时间基准与可比较性, 不动这些语义.

## Goals / Non-Goals

**Goals:**

- 新备份的时间戳统一取 UTC 秒级精度, 仍是 15 字符 `YYYYMMDDThhmmss`, 使同一目标的备份名在时钟稳定时字典序即时间序.
- 删除本地时区读取与 UTC 退化分支, 移除 `local-offset` feature, 不新增依赖.
- 保留命名形态, 同秒消歧序号, 完整名查找规则, 备份不回收, 以及 `undo` 先取快照再动手的顺序.
- 用跨 `TZ` 的子进程端到端用例锁定修复: 旧实现必然失败, 新实现恢复较新内容.
- 把时钟回拨与旧备份混放这两项残余风险写入 README 与 design.

**Non-Goals:**

- 不重命名, 迁移或删除任何既有备份; 不提供自动清理.
- 不在名字中加入 UTC 偏移, 不做偏移感知比较.
- 不用文件 mtime 或 birthtime 排序.
- 不引入单调序号, 持久化计数器或任何用于抵抗时钟回拨的状态.
- 不改变同秒消歧, `.partial` 排除, 报告格式, 退出码与其他 capability 的 delta.

## Decisions

### D1. 备份名时间戳统一取 UTC

`timestamp()` 改为直接调 `OffsetDateTime::now_utc()`, 再交给一个纯格式化函数 `format_timestamp(OffsetDateTime) -> String`: 先把时刻归一到 UTC (`to_offset(UtcOffset::UTC)`) 再取年月日时分秒, 生成 `YYYYMMDDThhmmss`. 删除 `timestamp_at(Option<OffsetDateTime>)` 的 `Option` 参数, `unwrap_or_else(now_utc)` 退化分支与相应单测. 归一化让单测可以用带 `+08:00` 偏移的固定时刻断言 UTC 化结果, 也避免调用方误传本地时刻时输出本地字段. `now_utc()` 只需要 `time` 的 `std` feature, 不需要 `local-offset`.

改写 `src/backup.rs:378-401` 的注释: 说明时间戳必须是 UTC, 因为 "取最新" 按 15 字符时间戳做字符串比较, 同一目标的备份必须共享同一时间轴; 明确写出 "不再有本地时区分支", 删除 "退化只影响字面值" 的错误断言.

备选方案与否决理由:

- 名字里带 UTC 偏移并做偏移感知比较: 否决. 命名会从 15 字符时间戳变成 "时间戳 + 偏移" 的更宽形态, `is_timestamp`, 查找规则, 报告与全部测试都要解析偏移; 非法或缺失偏移会引入新的失败分支; 旧名字仍然无法与带偏移的新名字可靠比较, 兼容面比统一 UTC 大得多, 而正确性没有额外收益.
- 改用文件 mtime: 否决. `openspec/specs/backup-fidelity/spec.md` 的 "备份保留修改时间" 要求备份的普通文件与目录具有与原对象相同的 mtime, 因此备份 mtime 是原对象的修改时间而不是备份发生时间; 它也可被用户改写, 且粒度受文件系统限制, 无法承担排序.
- 只写文档不改排序: 否决. 已复现的 "undo 恢复较旧内容" 是数据安全问题, 文档不能消除错误分支.

### D2. 移除 `local-offset` feature

`Cargo.toml` 的 `time` 依赖改为只保留默认 feature. 生产代码中不再有 `now_local()`, 移除 feature 后编译器会阻止本地时区调用重新混入. `time` 版本不变, 使用 `OffsetDateTime` 的其余格式化代码不变.

`Cargo.lock` 预计不变: 锁文件记录的是解析结果, `time` 的可选依赖即使未启用也会出现在依赖列表里. 实施时用 `git diff -- Cargo.lock` 与 `cargo check --locked` 复核; 若 Cargo 真的删除了不再需要的条目, 只接受删除, 不接受版本漂移.

备选方案与否决理由:

- 保留 `local-offset` 但不再调用: 否决. 保留平台特定的时区查询代码与可选依赖, 还会让后续改动误以为本地时间仍被支持; feature 统一也可能在其他依赖的启用下悄悄生效.
- 完全移除 `time` 依赖改用 `SystemTime` 手工换算: 否决. 需要自己实现 UTC 日历换算与闰年规则, 复杂度与回归面远大于收益; `time` 已在依赖中, 仅去掉一个 feature 更小.

### D3. 排序实现保持不变, 只收紧前提

`cmp_backup_key` 的比较顺序保持 "(时间戳字符串, 序号数值, 文件名兜底)": 定长 UTC 时间戳的字符串序与时刻序一致, 因此第一步不需要解析. `scan_backups` 的筛选, `complete_suffix_of`, `cmp_serial` 与 `is_timestamp` 全部不变, 只更新注释, 写明 "时间戳来自 UTC, 字符串序即时间序" 这一前提.

备选方案与否决理由:

- 每条候选先解析成 `OffsetDateTime` 再比较: 否决. 需要为非法日期增加失败分支, 而 `is_timestamp` 只校验字符形态; 字符串比较对定长格式是精确且全序的, 解析只会增加成本与不确定的坏数据语义.
- 按完整文件名字典序比较: 否决. 同秒序号 `10` 的字典序小于 `9`, 会取错备份, 主规格已禁止.

保留同秒消歧序号: 同一 UTC 秒内的多次备份仍按 `.2`, `.3` 递增; 时钟回拨导致的同秒重复也由序号消歧, 但回拨到更早的秒不在序号能修复的范围内 (见 D4).

### D4. 时钟回拨作为已知限制, 不引入状态

UTC 只消除时区混排, 不消除系统时钟本身向后跳. NTP 校时或手动改表后生成的备份可能携带更早的 UTC 时间戳, 于是它在排序中落在旧备份之前, 较新的内容不会被选中, `undo` 恢复的反而是时钟回拨前的那份. 本变更在 README 的已知限制与本文 Risks 中写明该残余风险.

备选方案与否决理由:

- 在备份目录持久化 "上次使用的时间戳或单调序号", 强制新名字不小于它: 否决. 引入可变状态与并发读写/原子更新问题; 状态被删除, 备份被复制到别的目录或机器后失效; 与 "备份只是同目录文件" 的无状态模型冲突.
- 拒绝时间戳不大于既有最新的备份: 否决. 会破坏合法的同秒连续备份, 也无法判断哪个是真实更新的内容; 等于把排序问题变成拒绝服务.
- 用 ctime 或 inode 兜底: 否决. ctime 随元数据修改变化且平台语义不同, inode 会复用, 都不能表达备份先后.

### D5. 旧备份不自动迁移

变更前的本地时区备份与新 UTC 备份共享完全相同的 15 字符形态, 无法从名字判断哪一份是旧语义, 也无法还原生成时的偏移. 自动重命名需要写用户文件, 在并发运行或备份被其他工具引用时有破坏性, 且仍然无法知道原始偏移. 因此不做迁移, 在 README 中建议: 若同一目标的备份需要可靠排序, 升级后清理或归档旧备份; 保留旧备份时, 旧名字可能看起来比新备份更新 (例如 `+08:00` 的名字比同一时刻的 UTC 名字大 8 小时), `undo` 仍可能选中它.

备选方案与否决理由:

- 忽略旧语义的备份名: 否决. 新旧名字同形, 无法区分; 强行忽略会孤立全部既有备份, 违反 "完整命名的备份参与查找" 的语义.
- 读取 birthtime 反推生成时刻: 否决. birthtime 不可移植, 复制备份会丢失或改写, 而且它也不记录当时的时区偏移.
- 自动重命名旧备份: 否决. 需要写用户文件, 与并发调用和外部引用竞争, 且没有可靠的偏移来源.

### D6. MODIFIED 块保留主规格的 requirement 标题

delta 中该 requirement 的标题逐字保留 "备份名携带秒级本地时间戳". OpenSpec 按标题匹配 MODIFIED, 归档时会拒绝标题不一致的块; 改名需要 `## RENAMED Requirements`, 不在本次允许的 delta 范围内. 规范正文与 Scenario 全部按 UTC 书写. 归档后如需让标题与正文一致, 由独立变更以 RENAMED 处理, 记入 Open Questions.

备选方案: 直接在 MODIFIED 块里把标题改成 "备份名携带秒级 UTC 时间戳". 否决理由: 标题与主规格不一致会让 MODIFIED 定位失败, 归档报 "not found"; 用 RENAMED 先改后改又超出本变更只允许 MODIFIED 两条 requirement 的边界. 代价是标题与正文暂时不一致, 已作为文档债记录.

## Risks / Trade-offs

- **时钟回拨使时间序与真实先后不一致** -> 无法在无状态前提下修复; 写入 README 已知限制, 建议对顺序敏感的用户在确认时钟稳定后再依赖 `undo` 的自动选择.
- **旧本地时间戳备份与新 UTC 备份混放** -> 写入 README 迁移限制, 建议升级后清理旧备份; 不自动删除, 残余风险持续到用户处理为止.
- **备份名的可读时间变为 UTC** -> 用户看到的字面小时会与本地时间不同; README 的备份命名与已知限制两处说明, 报告仍给出完整路径, 形态与长度不变.
- **名称相关的脚本可能依赖本地小时** -> 形态不变, 只改变绝对小时; 在 README 与发布说明中标注, 不提供兼容开关, 避免出现两套时间基准.
- **移除 feature 可能改变 `Cargo.lock`** -> 用 `git diff -- Cargo.lock` 确认无漂移, 用 `cargo check --locked` 与交叉目标检查锁定构建.
- **跨秒边界让端到端断言不稳** -> 测试只断言两个时间戳的差远小于时区偏移 (例如小于 60 秒), 不断言具体名字或精确相等; `TZ` 只设在子进程上, 不改测试进程的全局环境.
- **requirement 标题仍写 "本地"** -> 规范正文已明确 UTC; 记录为文档债, 由后续 RENAMED 变更修正, 不影响运行行为.

## Migration Plan

无数据迁移, 无配置或状态格式变化.

1. 升级后新生成的备份名一律是 UTC; 旧备份保持原名与原内容, 不重命名, 不删除.
2. README 增加两条说明: 备份名时间戳是 UTC; 旧本地时区备份与新备份混放时排序可能不可靠, 建议清理或归档旧备份, 不做自动迁移.
3. 回滚策略: 还原 `src/backup.rs` 的 `now_local()` 与 `timestamp_at(Option<...>)` 并恢复 `local-offset` feature. 回滚会让排序反转缺陷重新出现, 且新产生的 UTC 备份会与回滚后的本地备份混放; 因此回滚后同样建议清理备份并统一版本, 不提供自动转换.
4. 验证顺序: `cargo test --locked`; 跨 `TZ` 端到端用例; `./scripts/check.sh`; `cargo check --locked --target x86_64-unknown-linux-gnu` 与 `cargo check --locked --target x86_64-pc-windows-gnu`; 最后 `openspec validate "harden-backup-ordering" --strict`.

## Open Questions

- 是否在归档后用一个独立变更把 requirement 标题改为 "备份名携带秒级 UTC 时间戳" (需要 RENAMED delta, 与本变更的 MODIFIED 范围互斥).
- 是否在 README 给出旧备份清理的具体命令示例; 本变更只给建议, 避免文档直接鼓励删除用户文件.
