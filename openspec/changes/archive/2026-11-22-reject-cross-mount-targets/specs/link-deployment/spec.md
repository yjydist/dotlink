# Spec Delta

## ADDED Requirements

### Requirement: 目录替换不得跨越挂载边界删除内容

当 `replace_and_backup` 的目标是目录时, 在删除暂存目录之前 MUST 复核该目录及其后代; 发现挂载边界 MUST NOT 递归删除该边界之后的内容, MUST 尽力把暂存目录原子移回原路径并报告失败, MUST NOT 建立链接. 移回失败时 MUST 保留暂存目录并在说明中给出完整路径, MUST NOT 删除挂载内容. 删除 MUST 使用不跨挂载边界的递归实现, MUST NOT 直接使用可能跨越边界的递归删除. 该失败使该条目报告 `fail`, 退出码按既有判据为 1, token 词汇不变.

#### Scenario: 备份完成后目标内出现挂载点

- **WHEN** 目录备份已完成, 删除暂存对象之前目标目录内出现 tmpfs 挂载点
- **THEN** 该条目报告 `fail`, 挂载点及其内容保持原样, 目标路径恢复为原目录或说明给出暂存目录的完整路径, 不建立链接

#### Scenario: 目录内含挂载点时在备份阶段失败

- **WHEN** 目标目录在备份开始前就含 tmpfs 或 bind mount, 条目声明 `replace_and_backup`, 执行 `apply`
- **THEN** 该条目报告 `fail`, 目标目录与挂载内容保持原样, 不出现最终备份名, 不建立链接, 退出码 1

#### Scenario: 移回暂存目录失败

- **WHEN** 删除前发现挂载边界, 但原目标路径已被并发新建的内容占用
- **THEN** 新内容保持原样, 暂存目录不被删除, 该条目报告 `fail`, 说明同时给出挂载边界与暂存目录的完整路径

#### Scenario: 不含挂载点的目录正常替换

- **WHEN** 目标目录不含任何挂载点, 备份与身份复核均成功
- **THEN** 暂存目录按既有顺序删除, 新链接建立, 该行 token 为 `replace`
