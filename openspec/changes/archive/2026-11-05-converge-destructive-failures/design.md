# Design

## Context

四条破坏面在失败后的收敛性由现有代码决定:

- [apply.rs](../../../src/apply.rs):78 在 [apply.rs](../../../src/apply.rs):83 的 `write_backup` 之前记录 `ObjectIdentity`; 身份基准因此是"备份开始前的目标", 而不是 `write_backup` 实际复制的对象. 暂存复核失败时的说明 ([apply.rs](../../../src/apply.rs):187) 固定写成"备份之后目标被外部替换".
- [apply.rs](../../../src/apply.rs):97-102 在 `remove_staged` 成功后才 `create_link`; 建链失败时目标为空, 原内容只在备份里. `undo` 对 `Absent` 直接返回 `Ok` ([undo.rs](../../../src/undo.rs):56, [render.rs](../../../src/render.rs):328), 不恢复.
- [undo.rs](../../../src/undo.rs):63-72 暂存并复核链接后直接 `remove_file`; 失败时不回滚, 目标为空而链接留在暂存名, 下一次 `undo` 判 `Absent` 后不再重试.
- [undo.rs](../../../src/undo.rs):86-91 在恢复成功后用 `let _ = fs::remove_file(&staged)` 吞掉清理失败; 恢复失败的说明来自 [backup.rs](../../../src/backup.rs):222-225, 只给出目标路径, 不给所尝试的备份路径.

约束: 不新增命令或参数, 不引入状态文件, 不回收备份, 不把 `apply` / `undo` 事务化. 现有 `os::stage_aside`, `os::rename_noreplace` 与 `backup::restore_backup` 可复用.

## Goals / Non-Goals

**Goals:**

- 身份复核的基准与备份实际复制的对象一致, 失败说明准确区分"备份前被替换"与"备份后被替换".
- 替换末段建链失败时目标不丢内容, 备份保留且可从说明定位.
- `undo` 的移除失败可回滚并重试; 恢复成功后的暂存残留不再静默; 恢复失败说明给出所尝试的备份路径.
- 目标为空且同目录有完整备份时, `undo` 能恢复该备份, 使 `apply` 末段失败或崩溃后的状态可由下一条命令收敛.
- 每条新分支都有可控测试, 并保持既有正常路径不变.

**Non-Goals:**

- 不消除 `apply` / `undo` 与外部并发修改之间的全部竞态, 不串行化并发调用.
- 不回收, 不压缩, 不迁移备份; 不改变备份命名, 位置, 完整性与"恢复不消费备份"的语义.
- 不新增 token, 不改变 `cli-contract` 的两条件判据; 只扩展 `Absent` 在撤销 token 表中的编码.
- 不为 `apply` 末段失败引入事务日志或自动重试循环.

## Decisions

### D1. 身份基准由备份复制起点给出, 不再在备份前另取快照

`backup::copy_object` 当前第一行已经对源做 `symlink_metadata`. 让它返回该次复制的顶层对象元数据; `copy_to_staging` 与 `write_backup_at` 把它一路带回, `write_backup` 返回 `PublishedBackup { path, source_metadata }`. `apply` 删除 [apply.rs](../../../src/apply.rs):78 的预备份快照, 用 `ObjectIdentity::from_metadata(&source_metadata)` 得到身份, 交给 `stage_and_verify` 比较.

这样身份基准与备份内容同源: 备份复制的是 B, 复核就以 B 为准. 目标在备份前被换成 B 且删除时仍是 B, 则 B 已在备份中, 可以安全替换; 目标在备份后被换成 C, 则 C 与 B 不一致, C 被移回并保留. 暂存复核失败的说明改为"拒绝删除 {target}: 备份时的对象与删除时的对象不一致 (暂存对象的身份与备份实际复制的对象不同)", 不再断言替换发生在"备份之后".

- 备选: 保留预备份快照, 只改说明措辞. 否决理由: 原对象 A 在备份前被换成 B, 备份复制 B, 之后目标又换回 A 时, 旧基准 A 会通过复核并删除 A, 而备份里只有 B, A 没有进入备份. 这正是要修的内容可达性缺口, 改措辞不能修.
- 备选: 在 `write_backup` 返回后再对目标取一次快照. 否决理由: 备份与快照之间目标可能已被换成未进入备份的 C, 之后暂存 C 会与快照 C 一致并通过复核, 删除的仍是没有进入备份的对象.
- 备选: 把 `apply` 的 `ObjectIdentity` 移到 `os` 或 `backup` 作为共享类型. 否决理由: 本变更只需把复制起点的元数据带回 `apply`; 移动私有类型会扩大模块表面, 并与并行进行的路径身份工作产生不必要的重叠. 返回 `fs::Metadata` 并由 `apply` 现有转换函数吸收, 已足够表达语义.

残余窗口: `copy_object` 的 lstat 与随后的 `open` / `read_dir` 之间仍可被外部替换. 本变更加窄了基准, 但没有消除该窗口; 更彻底的做法是对已打开的句柄做 fstat 并从该句柄复制, 留给后续加固.

### D2. 建链失败时从刚发布的备份恢复, 备份不消费

`replace_with_backup` 改为接收本次备份路径. 顺序保持"暂存并复核 -> 删除暂存对象 -> 建链". 建链失败时调用 `backup::restore_backup(target, backup_path)`, 把备份的完整内容恢复到刚空出的目标:

- 恢复成功: 返回 `EntryFailed`, 说明为"建立链接失败: {原因}; 已从备份恢复原内容, 备份未删除", 由 `replace_and_backup` 保留的"原内容已备份到 {路径}"收尾. 目标重新拥有原内容, 备份仍在.
- 恢复失败: 说明为"建立链接失败: {原因}; 从备份恢复原内容失败: {恢复原因}, 备份未删除", 外层仍给出备份路径; 目标可能仍为空, 但用户能从说明同时拿到备份位置与恢复失败原因.
- 两种情况都不删除, 不改名备份; 该行 token 为 `fail`, 退出码 1.

- 备选: 建链失败后只报备份路径, 让用户手工复制. 否决理由: 目标为空, 工具没有把可达的内容放回去, 用户必须执行计划外的恢复步骤; 这正是本变更要关闭的缺口.
- 备选: 先把新链接建到临时名, 删除暂存对象后 rename 到目标. 否决理由: rename 仍可能失败, 仍需保留恢复分支, 却新增一个会残留的链接暂存名与清理路径; 直接恢复更小, 且不改变规格规定的删除后建链顺序.
- 备选: 回滚删除暂存对象, 把暂存对象移回. 否决理由: 暂存对象已被删除, 无法回滚; 只能从备份复制.

测试接缝沿用 [apply.rs](../../../src/apply.rs):247-265 的线程局部风格: 增加 `before_backup` 与"下一次建链失败"两个 `#[cfg(test)]` 注入点. 前者用于覆盖"备份前目标被替换", 后者让测试在备份额外布置目标占用, 以覆盖恢复成功与恢复失败两条路径. 生产构建不包含这两个注入点.

### D3. `undo` 移除暂存链接失败时先移回

把 `remove_link` 的删除段抽成 `remove_staged_link(target, staged)`. `fs::remove_file` 失败时:

1. 尝试 `os::rename_noreplace(staged, target)`.
2. 成功: 返回失败, 说明"移除链接 {target} 失败: {原因}; 已把链接移回原路径, 可重试". 下一次 `undo` 仍看到本工具的链接, 可再次尝试.
3. 失败: 返回失败, 说明"移除链接 {target} 失败: {原因}; 且移回原路径 {target} 失败: {回滚原因}; 链接暂存于 {staged}". 新内容不被覆盖, 暂存链接不被删除.

- 备选: 维持现状, 只报告暂存路径. 否决理由: 目标为空, 下一次 `undo` 判 `Absent` 并报 `ok`, 用户失去在工具内重试的机会; 与 `apply` 对非目录对象"删除失败先移回"的处理也不对称.
- 备选: 用只读父目录构造移除失败并顺带验证移回. 否决理由: 同一父目录不可写时 `rename` 也会失败, 只能覆盖"回滚失败"分支, 覆盖不了"移回成功"分支. 因此需要一个 `#[cfg(test)]` 的一次性移除失败注入点; 测试直接调用 `stage_verified_link` 与 `remove_staged_link`, 无需再加阶段钩子. 同一注入点也用于 D4 的"恢复后清理失败"测试, 使 cleanup 的 `remove_file` 可被一次性拒绝.

### D4. 恢复成功后的暂存清理失败必须报告残留

`replace_link_with_backup` 的 `Ok(())` 分支改为匹配 `fs::remove_file(&staged)`:

- 成功: 返回 `Ok`.
- 失败: 返回 `EntryFailed`, 说明"备份已恢复到 {target}; 清理旧链接副本 {staged} 失败: {原因}". 恢复出的内容保持原样, 不回滚, 不删除备份; 该行由 `undo` 的失败通道渲染为 `fail`, 退出码 1.

- 备选: 保留 `restore` token, 在说明末尾追加残留路径. 否决理由: `restore` 在汇总中属于成功列, 退出码会是 0, 脚本与用户都会把"有残留"当成成功; 现有的 `Result` 通道就是为执行失败准备的.
- 备选: 重试清理. 否决理由: 没有证据表明重试会成功, 可能放大 I/O 错误; 报告残留路径已足够让用户处理.
- 备选: 回滚恢复出的内容以回到"链接在暂存名"的状态. 否决理由: 内容已完整恢复, 回滚会再次让目标为空, 扩大而不是缩小缺口.

### D5. 目标为空且有完整备份时, `undo` 走 `restore`

- [lib.rs](../../../src/lib.rs):283-288 的备份快照从"仅链接态"扩展到 `LinkedCorrect | LinkedWrong | Absent`. 目录读取失败仍按 `fail` 处理并在动手前短路, 与 `backup-lifecycle` 的"目录读取失败不是没有备份"一致.
- [undo.rs](../../../src/undo.rs):56 的 `Absent` 分支改为: 有快照备份则 `restore_backup(target, backup)`, 无备份则 `Ok`. `Absent` 恢复不先移除任何对象; `restore_backup` 的排他落位已经拒绝覆盖期间新建的内容. 恢复失败时说明给出所尝试的备份路径.
- [render.rs](../../../src/render.rs):318-332 的 `undo_token` 改为 `Absent` + `has_backup` -> `Restore`, 否则 `Ok`; [render.rs](../../../src/render.rs):398-401 的 `restore` 说明按 `Current` 区分"已移除链接并从备份恢复"与"目标为空, 已从备份恢复".
- 退出码不改: `error::goal_reached(Command::Undo)` 已把 `Restore` 视为本次有撤销动作, 因此 `Absent` 恢复成功仍退 1; 恢复后目标为空且无备份时下一次 `undo` 才是 `ok` 退 0. 这符合现有两条件判据, 不需要动 `cli-contract`.

幂等性分析:

- 恢复后目标被恢复内容占用. 若内容不是本工具创建的链接 (普通文件, 目录, 仓库外链接), 下一次 `undo` 判 `Foreign*` -> `skip`, 退 1, 不再触碰备份.
- 若恢复内容本身是仓库根内的链接, 下一次 `undo` 判 `LinkedCorrect` / `LinkedWrong` 且有备份 -> `restore`, 再次移除该链接并恢复同一份备份; 目标内容与备份不变, 退 1. 这是既有的 restore-again 分支, 不会产生新备份.
- 恢复失败时目标仍为空, 备份仍在, 下一次 `undo` 可重试; 若期间目标被新内容占用, 下一次 `undo` 按占用物报 `skip`, 不覆盖.
- 无备份的 `Absent` 仍是 `ok` 退 0, 与现有幂等语义一致.

- 备选: 只改文档, 不扩展 `Absent` 的 token 表. 否决理由: "目标为空 + 备份存在"仍没有命令能恢复内容, 用户只能手工复制; 内容可达性缺口仍在.
- 备选: 新增 `undo --restore` 开关或独立子命令. 否决理由: 本变更明确不新增命令或参数, 且会让"是否恢复"变成第二个配置面.
- 备选: 让 `apply` 在目标为空且有备份时恢复. 否决理由: `apply` 的职责是部署链接, 它要么建链, 要么失败; 把恢复塞进 `apply` 会让同一状态在 `apply` 与 `undo` 下产生不同的内容结果.

### D6. 错误文案与测试覆盖

- 身份不一致: 统一为"备份时的对象与删除时的对象不一致", 删除"备份之后被外部替换"的断言式措辞. 既有"目标被替换成目录"与"正常替换"的说明不变.
- 恢复失败: 在 `undo` 与 `apply` 两个调用点组装条目错误时都附加所尝试的备份路径; 不改 `backup::restore_backup` 的底层 rename 错误文本, 避免 `apply` 外层再写一次同一路径而造成重复. 因此 `restore_backup` 仍只报告目标路径, 但两个调用点的可观察条目说明都会补齐 `backup` 路径. `undo` 的 `rollback_link` 在回滚前就把带备份路径的原因传进去, 因此回滚成功与失败两种说明都含备份路径.
- 测试:
  - `backup`: `write_backup` 返回的元数据与复制内容同源; 既有返回值解构调整后全部通过.
  - `apply`: 备份前替换 -> `replace`; 备份后替换普通文件 / 目录 / 符号链接 -> `fail` 且保留替换物; 建链失败 -> 目标恢复原内容, 备份保留; 建链失败且恢复失败 -> 说明同时含备份路径与恢复原因.
  - `undo`: 移除失败且移回成功 -> 目标仍是可重试的链接; 移除失败且移回失败 -> 暂存链接保留并给出路径; 恢复成功但清理失败 -> `fail` 且给出残留路径; 目标为空 + 备份 -> `restore`, 内容恢复, 备份保留; 第二次 `undo` -> `skip`; 无备份仍是 `ok`.
  - 端到端: `tests/undo.rs` 增加"目标为空但同目录有完整备份, 直接 undo -> restore"的用例, 断言退出码 1, 目标内容, 备份仍在; `tests/apply.rs` 保持既有建链失败不阻塞其余条目的用例, 替换路径的恢复断言由 `apply` 的单测接缝覆盖.

## Risks / Trade-offs

- [复制起点的 lstat 与 open/read_dir 之间仍有窄窗口] -> 本变更把基准从"备份前"推进到"复制起点", 缩小窗口但不消除; 在 Risks 与 README 的已知限制中如实说明, 后续可改为句柄 fstat.
- [建链失败后的恢复本身可能失败] -> 目标可能仍为空; 失败说明同时给出备份路径与恢复原因, 内容仍可从备份找回; 不承诺事务化.
- [目标为空 + 备份的 `undo` 由退 0 改为退 1] -> 这是用户可见的行为变化, proposal 标为 **BREAKING**, README 开头与命令表同步; 备份格式与恢复内容不变.
- [`Absent` 也要扫描备份目录] -> 目录不可读时该条目由 `ok` 改为 `fail`; 这与"目录读取失败不是没有备份"的既有语义一致, 避免把环境故障当成无备份.
- [恢复成功后清理失败现在报 `fail`] -> 内容已恢复但退出码为 1; 这比把残留藏进成功列更诚实, README 的已知限制说明残留需手工清理.
- [移除失败后移回可能再失败] -> 目标可能被并发内容占用; 保留暂存链接并给出路径, 下一次 `undo` 可能因目标被占用而 `skip`; 不覆盖用户内容.
- [测试注入点只存在于 `cfg(test)`] -> 生产路径无额外分支; 代价是注入点需要与真实错误路径保持同样的错误类型与收尾.

## Migration Plan

无数据迁移. 备份的命名, 位置, 完整性与保留策略不变; 已有备份可直接被新逻辑恢复. 回滚方式是还原对应代码提交; 已部署链接与备份不受影响.

行为变更:

- 备份复制开始前目标被替换, 且删除时仍是替换后的对象: 旧实现以备份前快照为准会失败, 新实现以备份实际复制的对象为准, 可以完成替换; 该对象已进入备份, 不丢失内容.
- 备份完成后目标被替换: 仍失败并移回替换物, 说明改为"备份时的对象与删除时的对象不一致".
- 替换末段建链失败: 目标不再保持为空, 而是从备份恢复原内容; 该行仍为 `fail` 并退 1.
- `undo` 移除暂存链接失败: 链接先被移回原路径, 下一次 `undo` 可重试; 移回失败时保留暂存链接并给出路径.
- `undo` 恢复成功但清理暂存链接失败: 行由 `restore` 改为 `fail`, 说明给出残留路径, 恢复出的内容不回滚.
- 目标为空且同目录有完整备份: `undo` 由 `ok` 退 0 改为 `restore` 并退 1, 目标被恢复内容占用.

README 需要同步的措辞:

1. 开头幂等段: "`undo` 在撤销后目标为空且同目录没有完整备份可恢复的清单上同样为 `ok` 并退 0; 若目标为空但同目录有完整备份, `undo` 恢复该备份, token 为 `restore` 并退 1, 恢复后按既有 `skip` 或 restore-again 分支处理."
2. "命令与退出码"表: `undo` 的作用改为"移除 dotlink 创建的链接, 并在存在备份时恢复; 目标为空但有完整备份时也恢复", 并注明这种恢复行计入成功列但退出码仍为 1.
3. "已知限制"的并发与部分失败条目: 补充"`apply` 末段建链失败会从备份恢复原内容, 恢复本身也可能失败; `undo` 移除链接失败会先移回, 恢复成功后的暂存清理失败会报告残留路径; 整个命令仍不是事务." 同时保留备份不自动回收的说明.
4. 若 README 其他位置出现"撤销后目标为空即退 0"的无条件表述, 一并限定为"无完整备份可恢复".

## Open Questions

- 是否把 `copy_object` 的身份基准进一步改为对已打开句柄 fstat, 以关闭 lstat 与 open/read_dir 之间的窄窗口? 本变更按已确认的范围只做到复制起点, 该问题不影响本次规格与任务拆分.
