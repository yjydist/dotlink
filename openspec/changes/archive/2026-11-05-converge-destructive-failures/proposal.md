# Proposal

## Why

破坏性路径在"中途失败/崩溃"后的收敛性有四个缺口: `apply` 的身份基准取在备份之前, 与"复核备份时的同一对象"的规格措辞不符; 替换末段建链失败时目标为空, 原内容只剩备份, 而 `undo` 对 `Absent` 报 `ok` 不恢复; `undo` 移除暂存链接失败时不回滚, 链接留在暂存名, 下一次 `undo` 判 `Absent` 后不再重试; 恢复成功后的暂存链接清理失败被静默吞掉, 恢复失败说明也不给所尝试的备份路径. 这些缺口使"失败后目标不丢内容, 且下一次命令能收敛"无法由工具自身保证.

## What Changes

- `backup::write_backup` 返回它在复制起点 lstat 到的对象身份, `apply` 的暂存复核改用该身份作为基准; 身份不一致时说明改为"备份时的对象与删除时的对象不一致", 并新增备份前与备份后目标被替换的两个 Scenario.
- `apply` 在删除已复核的暂存对象后建链失败时, 从本次刚发布的备份复制恢复原对象到目标; 备份保留, 不消费. 恢复也失败时说明同时给出备份路径与恢复失败原因. 通过 `apply` 既有的线程局部接缝风格注入建链失败, 覆盖恢复成功与恢复失败两条路径.
- `undo` 移除暂存链接失败时先尝试把链接原子 rename 回原路径, 使下一次 `undo` 可重试; 移回失败时保留链接与暂存路径说明. 恢复成功但清理暂存链接失败时不再静默, 改为报告残留路径并将该行报 `fail`.
- `undo` 在目标为空 (`Absent`) 且同目录存在完整备份时恢复该备份, token 为 `restore`; 无备份时仍为 `ok`. 退出码沿用现有两条件判据. 恢复失败说明给出所尝试的备份路径.
- **BREAKING**: "目标为空 + 同目录有完整备份"的 `undo` 由 `ok` 退 0 改为 `restore` 并退 1; 依赖旧行为的脚本需调整.
- 不新增命令或参数, 不引入状态文件, 不回收备份; 不把 `apply` / `undo` 事务化.

## Capabilities

### New Capabilities

无.

### Modified Capabilities

- `link-deployment`: 修改"替换删除前必须原子复核身份" (身份基准改为备份实际复制的对象, 更准确的措辞, 新增备份前与备份后替换的 Scenario); 新增"替换末段建链失败时恢复原对象".
- `link-teardown`: 修改"恢复失败时链接原样保留以便重试" (移除失败先移回, 恢复失败说明给出所尝试的备份路径, 清理失败报告残留); 修改"撤销的 token 由状态与备份有无共同决定" (目标为空且有完整备份 -> `restore`).

## Impact

- 代码: `src/backup.rs` (写备份返回复制起点身份), `src/apply.rs` (身份基准, 建链失败恢复, 恢复失败说明补齐备份路径, 测试接缝), `src/undo.rs` (移除失败回滚, 清理失败报告, 恢复失败说明补齐备份路径, `Absent` 恢复), `src/lib.rs` (`Absent` 也查备份快照), `src/render.rs` (`Absent` + 备份 -> `restore`, 说明措辞).
- 测试: `src/apply.rs`, `src/undo.rs`, `src/backup.rs` 的单元测试, 以及 `tests/apply.rs`, `tests/undo.rs`, `tests/conflict.rs` 中受影响的端到端用例.
- 文档: `README.md` 开头的幂等说明, "命令与退出码"表, 以及"已知限制"中的并发与部分失败措辞.
- 兼容性: 不新增依赖; 行为变化只发生在失败收敛与"目标为空 + 备份存在"的撤销; 备份命名, 保存位置与保留策略不变.
