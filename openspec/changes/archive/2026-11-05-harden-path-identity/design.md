# Design

## Context

现有校验全部基于 `os::normalize` 产出的路径字符串: [manifest.rs](../../../src/manifest.rs) 的 V-5 用 `HashMap<PathBuf, usize>` 判重, V-9 用 `==` 与 `starts_with` 比较基准路径, V-10 用 `==` 比较目标与源, V-11 用组件比较判断祖先关系. `os::normalize` 只解析已存在祖先段的符号链接 ([os/mod.rs](../../../src/os/mod.rs)), 不折叠大小写, 也不识别 firmlink 别名.

在大小写不敏感卷 (macOS 默认 APFS) 或存在 firmlink 的 macOS 上, 同一对象有多个合法写法. 实测: 别名形式的 `target` 指向仓库根或清单文件时四类校验全部放行, `apply` 先备份再删除整个仓库 / 替换 `dotlink.toml`; `source = "a"`, `target = "A"` 通过 V-10 后建出自指链接. 因此校验需要一条独立于字符串的"同一对象"判据.

## Goals / Non-Goals

**Goals:**

- 让 V-5, V-9, V-10, V-11 在受支持平台上无法被别名写法绕过.
- 保持"校验先于任何文件系统改动": 身份探测只读, 失败回退, 不产生新错误类型.
- 身份判等**单调收紧**: 只增加拒绝条件, 不改变任何原本的接受语义.
- 用平台门控测试锁定大小写别名与 firmlink 别名.

**Non-Goals:**

- 不改变 `classify`, `apply`, `undo` 的归属与判定语义; 链接归属仍按规范化路径包含性判断.
- 不引入状态文件, 不改变备份命名, 不改变任何报告 token 或退出码语义.
- 不处理大小写敏感卷上人为构造的硬链接重复 (硬链接身份相同会使 V-5/V-9 拒绝, 属可接受的保守行为).
- 不把整个校验变成与文件系统状态原子的过程; 外部在探测与执行之间改变文件系统仍属已知并发边界.

## Decisions

### D1. 身份判等原语: 设备号与 inode, 区分"落点对象"与"跟随后的对象"

新增两个原语: 目标侧用 `symlink_metadata` (lstat 语义, 判定落点对象本身), 基准点侧用 `metadata` (跟随符号链接, 使 `HOME` 是符号链接时物理形态也参与判等). 同一 `(st_dev, st_ino)` 即同一对象.

- 目标落点是符号链接时不跟随: 把该链接替换备份只会动链接本身, 不破坏它指向的目录, 保持现有语义.
- 基准点跟随: `HOME` 或仓库根本身就是符号链接时, 用户把同一个物理目录写在另一种形态下也应命中.
- 顺带收益: 清单文件是符号链接时, 其解析后的真实文件也进入 V-9 保护面, 关闭 README 已记录的残余风险; 需同步 README 措辞.
- 备选方案: 只做大小写折叠. 否决理由: 折叠规则依赖卷属性与 Unicode 归一化, 无法覆盖 firmlink, 且需要探测卷能力后才能决定是否折叠, 复杂度更高.

### D2. 基准点身份在解析前计算一次

`manifest::parse` 在条目循环之前构造不可变基准集合: 文件系统根 `/`, 仓库根, 仓库根的全部祖先, `HOME` 的书写形态与物理形态, 清单文件 (跟随符号链接). 每项尽力取得身份, 取不到则只保留字符串形态. 每份清单只做常数次 `stat`, 与条目数无关.

### D3. 目标侧身份按需探测, 失败退回字符串

对每个条目的 `target_path` 做一次 lstat: 存在且与任一基准身份相同即按 V-9 拒绝. 目标不存在或 lstat 失败 (权限, I/O) 时退回既有字符串比较, 因为此时不存在"同一对象"可言. 不新增清单错误, 也不改变不可读路径仍由 `classify` 报 `fail` 的既有语义.

V-5 与 V-10 复用同一次 lstat: 目标存在时与已收集的身份比较. V-5 的重复判定为"规范化字符串相等 或 两侧都存在且身份相同"; V-10 为"字符串相等 或 两侧都存在且身份相同". 由于 V-9 已先拒绝退化落点, 这里的身份比较不会遮蔽更严重的错误说明.

### D4. V-11 用"祖先身份集合"覆盖别名嵌套

只在目标与源上分别比较身份不足以发现"别名形式的目录包含". 做法: 为已存在的源构建身份 -> 条目下标映射; 对每个目标, 沿 `ancestors` 逐个探测身份并与源身份集合比较 (任一侧身份相同即视为包含/被包含); 再为已存在的目标构建身份映射, 对每个源同样沿祖先探测. 祖先探测复用目标 lstat 得到的第一手信息时仍要逐级 stat, 属 O(条目数 x 深度) 次只读调用; dotfile 清单规模下可接受, 且只在路径存在时才探测.

- 备选方案: 用 `canonicalize` 判等. 否决理由: 待部署目标通常不存在, 且它会把最后一层符号链接也解析掉, 改变既有语义.
- 残余风险: 两侧都不存在的别名路径无法判等 (没有对象可比), 见 Risks.

### D5. 测试按卷能力门控, 不伪造平台行为

新增测试辅助: 建临时文件后 `stat` 其大小写变体, 若能取到同一身份则判定卷大小写不敏感, 运行别名用例, 否则跳过; firmlink 用例仅在 macOS 且 `/System/Volumes/Data/Users/<当前用户>` 与 `HOME` 同身份时运行. 与项目既有的 "root 环境下跳过权限用例" 风格一致: 环境不满足时跳过并打印原因, 而不是让用例静默失效.

## Risks / Trade-offs

- [别名清单被整体拒绝属 BREAKING] -> 变更说明与 README 明示; 拒绝发生在任何改动之前, 用户改回规范写法即可.
- [身份判等引入了额外的只读 stat] -> 基准点常数次; 条目侧最多 O(条目数 x 路径深度), 且仅在路径存在时发生; 清单规模通常很小.
- [网络文件系统的 inode 可能与本地语义不同] -> 身份只用于"拒绝", 取不到或跨挂载点自然回退字符串比较; 不引入新的失败.
- [两侧都不存在的别名路径仍可能漏判] -> 目标尚不存在时没有对象可比; 这类写法在建链后由 `classify` 的链接归属复核接手, 属已知并发边界, 写入 design 与 README 的已知限制.
- [硬链接被 V-5 判重] -> 两个 target 是同一文件的硬链接时按"同一对象"拒绝, 符合 V-5 语义, 属预期收紧.

## Migration Plan

一次性变更, 无数据迁移. 回滚方式是还原 `manifest.rs` 与 `os/mod.rs` 的提交; 已部署的链接与备份不受影响, 因为身份判等只作用于清单校验阶段.
