## ADDED Requirements

### Requirement: 清单校验 V-9: 受保护落点

`target` 规范化后命中文件系统根 `/`, 当前用户主目录, 仓库根本身或其祖先 (如 `.` / `..`), 或清单文件自身 (仓库根下的 `dotlink.toml`) 时 MUST 整体拒绝, 说明 MUST 指出条目下标与书写形态. 这些落点一旦被替换备份, 毁掉的是整个文件系统, 整个主目录或源仓库; 替换清单文件自身会让后续命令失去唯一配置源. `~/sub` 与 `/etc/hosts` 这类合法落点不受影响.

#### Scenario: 裸 ~ 作为落点

- **WHEN** 某条目写 `target = "~"`
- **THEN** 整体拒绝, 退出码 2, 说明指出不能以主目录本身为落点

#### Scenario: 仓库根作为落点

- **WHEN** 某条目写 `target = "."` 或 `target = "sub/../.."`
- **THEN** 整体拒绝, 说明指出不能以源仓库为落点

#### Scenario: 清单文件自身作为落点

- **WHEN** 某条目写 `target = "dotlink.toml"` 或等价的绝对路径
- **THEN** 整体拒绝, 退出码 2, 说明指出不能以清单文件自身为落点

### Requirement: 清单校验 V-9a: 主目录落点的两种形态

主目录比较以 `HOME` 可解析为前提: `HOME` 缺失, 空值或为相对路径时无法确定主目录, 该项比较不适用, 清单 MUST NOT 因 `HOME` 不可用而被拒绝 (与"主目录解析"一致). 主目录的判别 MUST 同时覆盖 `HOME` 的书写形态与其解析末尾符号链接后的物理形态: `HOME` 自身可能是符号链接, 只比较其中一种形态会让写在另一种形态下的主目录落点漏过.

#### Scenario: 主目录路径本身是符号链接

- **WHEN** `HOME` 本身是一个符号链接, 而某条目把 `target` 写成该主目录解析符号链接后的物理路径
- **THEN** 整体拒绝, 退出码 2, 说明指出不能以主目录本身为落点

### Requirement: 清单校验 V-9b: 落点命中按文件系统身份判定

目标落点存在时, 命中判定 MUST 同时比较文件系统身份 (设备号与 inode): 与任一基准点指向同一对象的其它写法 (大小写别名, firmlink 别名) 同样命中. 身份读取不可用 (路径不存在或元数据读取失败) 时 MUST 退回规范化字符串比较, MUST NOT 因此拒绝清单.

#### Scenario: 大小写别名形式的仓库根

- **WHEN** 在大小写不敏感的文件系统上, 某条目把 `target` 写成仓库根路径的大小写变体
- **THEN** 整体拒绝, 退出码 2, 说明指出不能以源仓库为落点, 而不是当作普通目录备份后替换

#### Scenario: 别名形式的清单文件

- **WHEN** 某条目把 `target` 写成清单文件路径的另一种写法 (大小写变体或等价别名)
- **THEN** 整体拒绝, 退出码 2, 说明指出不能以清单文件自身为落点

#### Scenario: firmlink 别名形式的主目录

- **WHEN** 在 macOS 上, 某条目把 `target` 写成主目录的 firmlink 别名路径 (如 `/System/Volumes/Data/Users/<用户>`)
- **THEN** 整体拒绝, 退出码 2, 说明指出不能以主目录本身为落点

#### Scenario: 不存在的落点只做字符串比较

- **WHEN** 某条目的 `target` 不存在, 且其规范化字符串不等于任何基准路径
- **THEN** 清单被接受, 身份判等不可用不会使校验失败
