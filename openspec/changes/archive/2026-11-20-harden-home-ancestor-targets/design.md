# Design

## Context

见 `proposal.md` 的 Why. 当前 V-9 在 `src/manifest.rs` 的 `reject_degenerate_target` 中按四个基准判定: 文件系统根, 主目录 (书写形态与物理形态), 仓库根及其祖先, 清单文件自身. 主目录判定只做相等比较, 因此 `~/..` 这类祖先落点会通过; 仓库祖先检查只在仓库恰好位于该落点之下时偶然命中, 不是契约.

现有可复用的基础设施:

- `os::normalize` 做词法规范化, 刻意不解析末段, 因为目标通常是待部署的链接.
- `physical_home` 用探针子项让 `HOME` 成为祖先段, 从而解析出物理形态.
- `BaselineIdentities` 在条目循环之前一次性收集基准点的文件系统身份, 每个条目只做常数次比较.
- 身份不可用时全局退回规范化字符串比较, 且不得因此拒绝清单.
- `HOME` 不可用时 `home` 与 `home_physical` 都为 `None`; 需要 `~` 的条目已由 V-6 报错, 绝对路径不得因此被拒.

## Goals / Non-Goals

**Goals:**

- 把"主目录本身"的保护面扩展到"主目录的祖先", 同时覆盖书写形态与物理形态.
- 让以 `~` 简写书写, 经 `..` 离开主目录的落点 (如 `~//../x`) 也被拒绝, 使 `~` 形态只表达主目录及其之下.
- 落点存在时用文件系统身份命中祖先别名; 身份不可用时退回字符串比较.
- 保持合法落点 `~/sub`, `/etc/hosts`, 仓库内相对路径以及 `HOME` 缺失时的绝对路径不受影响.
- 错误说明继续指出条目下标与书写形态.

**Non-Goals:**

- 不改 `os::normalize` 的语义, 不引入 `Path::canonicalize`.
- 不扩大到"禁止所有绝对 target"或"禁止 `HOME` 之外的任何 target".
- 不改变 V-9, V-9a, V-9b 已定义的根 / 主目录本身 / 仓库祖先 / 清单文件判定.
- 不处理校验与 `apply` 之间的并发替换 (校验是快照).

## Decisions

### D1: 在 `reject_degenerate_target` 中增加祖先判定

在现有主目录相等比较之后, 增加 `home.starts_with(landing) || home_physical.starts_with(landing)` 形式的祖先判定. 两个形态都要检查: `HOME` 本身可能是符号链接, 只比较书写形态会让物理形态下的祖先漏过. 文件系统根 `/` 已在前一项被拒绝, 因此该判定只需覆盖主目录的真祖先.

被否决的备选方案:

- **只保护 `HOME` 本身**: 正是当前缺陷, 祖先落点在 `replace_and_backup` 下会删除包含主目录的整棵树.
- **只靠仓库祖先检查**: 仓库位于 `HOME` 之外时完全不生效, 且它保护的是源仓库而不是主目录, 语义错位.
- **禁止所有绝对 `target`**: 会误伤 `/etc/hosts` 等合法配置, 远超本次安全目标.

### D2: `~` 简写不得经 `..` 离开主目录 (按词法折叠, 不解析符号链接)

祖先判定只能命中 `~/..` 这类规范化后恰好等于祖先的落点, 不能命中 `~//../x` 这种祖先之下的子路径. 为满足 V-9c 的场景, 对以 `~` 或 `~/` 开头的书写形态增加判定: 把 `HOME` 与剩余段按 `Path::components` 做纯词法折叠 (只消去 `.` 与 `..`, 不访问文件系统, 不解析符号链接), 若结果不再是 `HOME` 或其子路径, 整体拒绝. `HOME` 不可用时跳过该判定; 这类条目本就需要 `~` 展开, 已由 V-6 处理.

不能用"展开后 `landing.starts_with(home)`"代替词法折叠: `os::normalize` 会解析已存在的祖先符号链接, 于是 `~/config/file` 在 `~/config -> /mnt/config` 时会被误拒, 而这正是用户有意配置的合法结构. 词法折叠只拦截 `..` 逃逸, 与规格的 "经 `..` 离开" 一致. 若 `~/link` 本身是指向 `HOME` 祖先的符号链接, 祖先判定仍会在规范化后命中并拒绝.

被否决的备选方案:

- **只做祖先判定**: `~//../x` 仍会被接受, 与 V-9c 的场景冲突.
- **用规范化后的 `landing` 判定 `~` 逃逸**: 会连带拒绝指向主目录外部的合法符号链接子目录, 超出 "经 `..` 离开" 的契约面.
- **把 `~` 形态一律限制在 `HOME` 之下但允许绝对路径离开**: 这就是本决策; 绝对路径仍可指向 `/etc/hosts` 等合法位置, 放行面不受影响.

### D3: `BaselineIdentities` 收集 `HOME` 祖先的身份

在 `BaselineIdentities::collect` 中, 对 `home` 与 `home_physical` 的每一条 `ancestors()` 调用 `os::basis_identity`, 去重后与主目录身份合并为一个集合. `reject_degenerate_target` 在 `landing_identity` 存在时用 `contains` 命中该集合, 归入"主目录的祖先"错误. 数量只与 `HOME` 深度有关, 与条目数无关, 每份清单仍是常数次 `stat`.

被否决的备选方案:

- **对每个条目调用 `canonicalize` 比较**: 目标通常不存在, `canonicalize` 会失败; 且与现有"不使用 `canonicalize`"的规格立场冲突.
- **只比较字符串**: 会漏掉大小写不敏感卷与前缀形态下的祖先别名, 与 V-9b 的身份判定立场不一致.

### D4: 身份不可用时退回字符串比较

身份集合取不到某个基准点时, 该基准点不进入集合, 只保留 `starts_with` 的字符串判定; 落点身份取不到时跳过身份比较. 两者都不得导致拒绝清单, 延续 V-9b 的既有契约.

### D5: 独立的错误说明

新增一条"主目录的祖先"说明, 与"主目录本身"区分, 文案仍由 `invalid_entry` 加 `entry[N]` 前缀, 并引用清单中的书写形态. 这样用户能看出命中的是祖先而不是主目录本身.

## Risks / Trade-offs

- [兼容性收紧] 旧版接受的 `~/..`, `~//../x` 与 `HOME` 父目录绝对路径现在退 2. 缓解: 在 README 的 V-9 段落明确标注为兼容性收紧, 错误说明给出条目下标与书写形态; 用户可改用主目录之下的合法落点.
- [`~` 逃逸判定范围扩大] 除祖先外, `~/../sibling` 这类非祖先的 `~` 逃逸也会被拒. 这是有意选择, 用于兑现 V-9c 的 `~//../x` 场景. 缓解: 在规格与 README 中写明 `~` 形态只表达主目录及其之下.
- [身份读取成本] 每个祖先目录多一次 `stat`. 缓解: 常量次且去重; `HOME` 不可用时直接跳过.
- [大小写别名只在可读身份时命中] 某些文件系统或权限下 `basis_identity` 失败. 缓解: 退回字符串比较, 与本条现有的 V-9b 行为一致, 且明确不因此拒绝清单.
- [`HOME` 为 `/`] 祖先集合与根重合, 由既有的文件系统根判定先行拒绝, 不产生额外行为.

## Migration Plan

1. 先在 `src/manifest.rs` 扩展现有校验, 再补单测与端到端用例.
2. 同步更新 README 的 V-9 段落, 标注 **BREAKING**.
3. 无数据迁移, 无状态文件变化. 回滚只需撤销新增校验 (祖先判定, `~` 逃逸判定与身份集合), 旧版清单即可恢复接受; 不需要修复已部署的链接.

## Open Questions

- 错误说明是否应在"主目录的祖先"文案中额外给出规范化后的祖先路径? 这属于文案细节, 不改变规格与校验行为, 可在实现时按可读性决定.
