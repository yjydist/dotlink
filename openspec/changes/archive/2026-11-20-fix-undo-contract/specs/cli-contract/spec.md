# Spec Delta

## MODIFIED Requirements

### Requirement: 各命令的目标谓词

条件一 MUST 按命令取下列唯一解释: `apply` 要求每个条目的目标路径都已是指向其源条目的正确链接; `undo` 要求每个条目的目标路径上都不存在本工具创建的链接, 且本次没有从备份恢复任何内容; `preview` 要求没有任何条目需要执行动作; `status` 要求清单与实际状态完全一致. `missing` 与 `fail` 不计入条件一 (见 `entry-classification` 的"目标谓词对特殊状态的计数基准"), 其残留待办只由条件二表达; `preview` 的"需要动作"按可消除的待办计, `conflict` 虽没有文件系统动作, 也代表本次未能达成期望, 因而计入条件一为假.

#### Scenario: 未部署清单上的预览

- **WHEN** 清单中的条目全部未部署, 执行 `preview`
- **THEN** 目标谓词为假, 退出码 1

#### Scenario: 空目标且有备份的撤销

- **WHEN** 目标路径本就不存在, 同目录有一份完整备份, 执行 `undo`
- **THEN** 备份被恢复, token 为 `restore`, 计入成功列, 但目标谓词为假, 退出码 1

#### Scenario: 空目标且无备份的撤销

- **WHEN** 目标路径本就不存在, 同目录没有备份, 执行 `undo`
- **THEN** token 为 `ok`, 目标谓词为真, 退出码 0

### Requirement: `--help` 文本自带退出码语义

每个子命令的 `--help` MUST 写明退出码的含义, 使用户仅凭命令行输出即可判断每个条目的结果与下一步动作. `--help` 文本 MUST 至少说明: 退出 1 可能表示有待办也可能包含跳过或失败; 退出码 2 的两重含义及其区分方式; 只读命令在有待办时同样退 1.

#### Scenario: 查看子命令帮助

- **WHEN** 用户执行 `dotlink preview --help`
- **THEN** 输出包含退出码 0 / 1 / 2 / 3 的含义说明

#### Scenario: 帮助提示脚本用法

- **WHEN** 用户查看任一子命令的 `--help`
- **THEN** 输出提示在 `set -e` 脚本中不应裸调只读命令, 并给出按退出码分支的示例

#### Scenario: undo 帮助写明完整目标谓词

- **WHEN** 用户执行 `dotlink undo --help`
- **THEN** 输出同时说明"目标路径上不存在本工具创建的链接"与"本次没有从备份恢复任何内容", 不得只写前半句而让 `Absent + 有备份` 暗示退出 0
