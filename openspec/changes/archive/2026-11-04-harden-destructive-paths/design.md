# Design

## Context

当前有三条破坏面需要收紧:

- `manifest::reject_degenerate_target` 只比较文件系统根, 主目录与仓库根/祖先, 不比较清单文件自身 (`src/manifest.rs:363`).
- `apply::replace_and_backup` 在 `write_backup` 之后调用 `remove_object` (`src/apply.rs:66`), 后者先 `lstat` 再删除; 两步之间目标被替换时, 可能删掉未备份的新对象.
- `undo::remove_link` 先 `ensure_still_a_link` 再 `remove_file` (`src/undo.rs:55`), 同样的竞态存在; 且该复核只要求"仍是符号链接", 不重新确认归属.
- `backup::write_backup_at` 在复制完成后直接 rename 到最终名 (`src/backup.rs:163`), 没有在删除原对象前把数据同步到稳定存储.

`os::rename_noreplace` 已提供原子不覆盖的 rename, `undo::stage_link` 已有"移到同目录暂存名"的实现, 可复用为统一的破坏面原语.

## Goals / Non-Goals

**Goals:**

- 拒绝以清单文件自身 (`dotlink.toml`) 为 target 的清单.
- 删除被替换对象前, 先原子暂存并复核对象身份; 身份不一致时移回并失败, 不删除未备份内容.
- `undo` 的移除与恢复前, 先原子暂存并复核"仍是符号链接且目标仍属于本工具".
- 备份发布前把复制产物同步到稳定存储; 同步失败不发布最终名, 不删除原对象.
- 用单元测试与端到端测试锁定正常路径, 身份不一致路径与同步失败路径.

**Non-Goals:**

- 不把整个 `apply` / `undo` 变成事务, 不串行化并发调用, 不隔离外部对源或父目录的修改.
- 不保护 `.git/**` 或其他仓库内部路径; 只保护清单文件自身与既有的退化落点.
- 不改变 `on_conflict` 语义, 不改变备份命名, 不自动回收备份.
- 不保留所有权, ACL, 硬链接或稀疏结构.
- 不在 Windows 等不受支持平台验证运行时; 现有平台门禁不变.

## Decisions

### D1. 清单自指用归一化路径精确比较

`reject_degenerate_target` 增加一个比较基准: `repo.join(MANIFEST_NAME)`.`repo` 与 `landing` 都已经过 `os::normalize`, 因此 `target = "dotlink.toml"`, `target = "./dotlink.toml"` 与等价的绝对路径都会被拒绝.备选方案是拒绝仓库根下所有非源路径; 否决理由是相对 target 是文档化能力, 不能整体禁用.

限制: 若清单文件本身是符号链接, 这里保护的是清单路径自身, 不是它解析后的最终文件; 该残余风险写入 README 的已知限制.

### D2. 替换删除改为"暂存 -> 复核 -> 删除"

新增一个对象身份快照: 在 `write_backup` 之前用 `symlink_metadata` 记录目标的 `(dev, ino, file_type)`. 备份完成后:

1. 用 `rename_noreplace` 把目标移到同目录暂存名 `<target>.<pid>.dotlink-replace.partial` (占用时追加序号).
2. 对暂存名再做 `symlink_metadata`, 比较 `(dev, ino, file_type)`.
3. 一致: 删除暂存对象 (目录递归), 再建立链接.
4. 不一致: 用 `rename_noreplace` 把暂存对象移回原路径 (原路径为空时); 若移回失败, 说明中给出暂存路径与备份路径, 条目失败.
5. 删除暂存对象失败: 该对象已被备份, 报告备份路径与暂存路径, 不建立链接; 若可以原子移回则先移回.

这样删除步骤只作用于"身份已确认"的对象, 外部替换物不会被当作旧对象删除.备选方案是先删再对比, 不能解决竞态; 否决.

身份比较只覆盖 `dev`, `ino` 与文件类型; inode 复用的理论窗口不处理, 记录为残余风险.

### D3. `undo` 复用暂存并复核归属

`remove_link` 不再"先复核再删除", 改为:

1. 复用 `stage_link` 把目标原子移到暂存名.
2. 读取暂存对象的 `symlink_metadata`; 不是符号链接则移回并失败.
3. 读取暂存链接文本, 用与 `classify` 相同的 `link_destination` 解析并 `os::normalize`; 若目标不等于本条目的 `source_path` 且不落在仓库根内, 视为外部链接, 移回并失败.
4. 通过后删除暂存链接.

`replace_link_with_backup` 已经调用 `stage_link`; 在同一位置插入第 2, 3 步复核, 通过后再恢复备份.

为了复用解析逻辑, 把 `classify::link_destination` 提升为 `os` 层的共享函数; `classify` 与 `undo` 都调用它.`undo_entry` 增加一个已规范化的 `repo_root` 参数, 由 `lib.rs::undo` 在循环外计算一次.

备选方案是只复核"仍是符号链接"; 否决理由是无法阻止替换成仓库外链接后被删除, 与本次加固目标不符.

### D4. 备份发布前同步数据

在 `copy_object` 内:

- 普通文件: 复制内容与应用元数据后, 对输出文件调用 `sync_all`.
- 目录: 子项全部复制并应用元数据后, 对目录调用 `sync_all`.
- 符号链接: 无法对链接自身 sync; 由发布后的父目录同步覆盖.

在 `write_backup_at` 的 `rename_noreplace` 成功后, 对最终名的父目录调用 `sync_all`. `restore_backup` 同样在 rename 后同步父目录; 由于 `copy_object` 已同步内容, 恢复路径同样具备持久性.

rename 是否已经发生决定失败语义: rename 之前的复制产物同步失败不发布最终名; rename 之后的父目录同步失败无法回滚已发布的名字, 因此该条目失败, 说明给出已发布的备份路径, 原对象保持原样. 恢复路径同理: rename 成功后的父目录同步失败表示内容已就位, 该条目仍报告失败, 调用方 MUST NOT 回滚暂存链接, 只清理旧链接副本, 并在说明中指出内容已恢复.

平台不支持同步 (`Unsupported`) 时沿用 `skip_unsupported` 的降级策略, 其他同步错误使该条目失败. 该取舍与现有扩展属性/ mtime 的降级语义一致; 代价是部分网络文件系统上仍可能不满足强持久性.

### D5. 测试接缝

- 身份不一致: 在 `apply` 的替换路径中增加一个 `#[cfg(test)]` 钩子, 允许测试在备份完成后,暂存前替换目标; 或在 `stage_and_verify` 助手上直接构造"快照 A, 暂存 B"的局面.后者更小, 优先.
- 同步失败: 为 `sync_file` / `sync_dir` 增加按作用域区分的 `#[cfg(test)]` 注入点 (全部 / 仅目录), 模拟 `EIO`; 断言复制阶段失败不发布最终名且原对象保留, rename 后的父目录失败在说明中给出已发布路径; 恢复的 rename 后失败不回滚并保留已恢复内容.
- 清单自指: 直接走 `manifest::parse` 与端到端 `preview` / `apply`, 断言退出码 2 且文件系统不变.
- `undo` 归属复核: 单测构造"暂存后链接被换成仓库外链接"的场景, 断言移回,不删除,报告失败.
- 正常路径: 现有 `replace_and_backup`, `undo`, metadata 测试保持通过, 确保暂存与同步没有改变用户可见结果.

### D6. 错误说明

失败说明继续包含备份路径; 新增暂存路径时, 同时给出"原内容已备份到 X"与"对象暂存于 Y". 不改变退出码映射: 条目失败仍是 `fail` 与退出码 1.

## Risks / Trade-offs

- **fsync 增加大量 syscall** -> 备份本来就复制全部内容; 目录树越大, 额外同步越明显.README 的已知限制说明备份变慢, 但不提供关闭开关, 避免出现第二个配置面.
- **身份复核在极端并发下误报** -> 外部替换或 inode 复用会让复核失败; 这是安全失败, 原对象移回, 不会删除未备份内容.
- **目录删除失败可能留下部分删除的暂存树** -> 该对象已经备份, 报告备份路径与暂存路径; 不回滚部分删除的树, 避免把半成品移回.
- **清单符号链接的最终目标未被保护** -> 记录残余风险; 如需完全覆盖, 需要解析清单最终段, 会引入额外文件系统语义.
- **`undo` 归属复核收紧** -> 极端竞态下原本会被删除的仓库外链接现在会保留并失败; 这是刻意的安全修正, 需要更新 `link-teardown` 的 Scenario 与测试.
- **平台降级** -> `Unsupported` 同步不使备份失败, 与现有元数据降级一致; 强持久性只在支持的平台上承诺.

## Migration Plan

无数据迁移.清单校验收紧会让此前能通过校验的 `target = "dotlink.toml"` 清单改为退 2; 在 README 与归档说明中注明.回滚时恢复 V-9, 删除暂存/同步逻辑与对应测试即可; 已有备份文件不受影响.

## Open Questions

- 是否把 `.git/**` 也纳入 V-9; 本变更不处理, 留待后续.
- 是否需要在同步失败时提供显式的"降级"诊断; 当前按 `Unsupported` 静默降级, 与其他元数据一致.
