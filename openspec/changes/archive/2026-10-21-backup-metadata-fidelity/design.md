# Design

## Context

- 备份与恢复共用同一条复制路径: `write_backup` 与 `restore_backup` 都调用 `src/backup.rs` 的 `copy_object`; 后者递归处理目录, 复制文件内容与权限位, 对符号链接只复制链接文本. 两者都先写入进程级唯一的 `.partial` 暂存名, 内容落定后才以原子不覆盖移动发布.
- 现有失败语义: `copy_object` 返回 `io::Result`, `finish_copy` 在失败时尽力清理本次创建的暂存对象; 备份失败时原对象不删除, `apply` 将该条目报为 `fail`. 恢复失败时链接回滚到原位.
- `Cargo.toml` 禁止 `unsafe`, 且 `rustix` 仅对 macOS/Linux 启用. `rustix` 1.1.5 的 `fs` 特性已提供 `listxattr` / `getxattr` / `setxattr` 与 `utimensat`, 无需新增依赖, 也不需要手写 FFI.
- 实测约束: 在 macOS 上对权限位 0444 的文件调用 `setxattr` 返回 `EACCES`, 因此扩展属性必须在最终 `chmod` 之前设置. 目录的 mtime 会被子项创建改变, 因此必须在子树复制完成后设置. macOS 的 ACL 不出现在 `listxattr` 结果中, 无法通过通用扩展属性路径复制.

## Goals / Non-Goals

**Goals:**

- 备份对象与恢复目标在内容, 类型, 权限位之外, 同时保留 mtime 与全部可读取的扩展属性.
- 备份与恢复继续共用同一个复制原语, 避免两者元数据行为漂移.
- 保持现有原子性与失败语义: 元数据未落定前不发布最终备份名; 失败时原对象原样保留.
- 不新增依赖, 不改变 CLI, 输出 token 或退出码.

**Non-Goals:**

- 所有权与组 (需要特权, 且备份应归执行用户所有).
- ACL (macOS 不通过 `listxattr` 暴露; Linux 若以扩展属性暴露则按通用路径尽力复制, 但不单独承诺).
- 硬链接身份, 稀疏文件结构, 特殊文件.
- 符号链接自身的 mtime 与扩展属性 (只保留链接文本).
- atime (复制本身会改变它, 保留没有可靠意义) 与断电持久性 (`fsync`).
- 为旧备份补写元数据; 旧备份按其所记录的元数据恢复.

## Decisions

### 1. 扩展现有 `copy_object`, 不新增并行复制路径

在每个对象的内容落定后, 统一应用元数据; 目录在递归返回后应用, 因此天然满足"子项复制完成后再设目录 mtime". 恢复复用同一函数, 从备份对象读取元数据并写到目标, 不需要第二套逻辑.

替代方案是为备份和恢复各写一个元数据遍历器: 递归顺序与错误分类会重复, 且日后容易只修一侧.

### 2. 元数据应用顺序: 扩展属性 -> 权限位 -> mtime

- 先设扩展属性: 文件与目录以 `0600` / `0700` 创建期间仍可写, 避免最终只读权限导致 `setxattr` 返回 `EACCES` (已实测).
- 再设权限位: `chmod` 只改变 ctime, 不改变 mtime.
- 最后设 mtime: 前面的元数据写入不会改变 mtime, 但目录的子项创建会, 放在最后可覆盖全过程.

### 3. 平台能力收敛在 `os` 层

在 `src/os` 增加元数据复制与时间设置原语: macOS/Linux 用 `rustix` 实现, 其他平台提供返回 `Unsupported` 的 stub, 保持 `backup.rs` 与平台无关. 这与现有 `create_symlink` / `rename_noreplace` 的门禁方式一致, 也保证 Windows 上仍可编译.

### 4. 扩展属性采用尽力而为的逐属性错误分类

- 枚举或读取时:`ENOTSUP` / `EOPNOTSUPP` / `ENOSYS` 视为该文件系统不提供扩展属性, 整体跳过; `ENODATA` 视为属性在列举与读取之间消失, 跳过该属性.
- `ERANGE` 表示缓冲区不足, 增大缓冲后重试同一属性.
- 设置时:`ENOTSUP` / `EOPNOTSUPP` / `ENOSYS` / `EPERM` / `EACCES` 跳过该属性并继续; 内核保护属性 (如 macOS 的 `com.apple.provenance`) 因此不会让备份失败.
- 其他错误 (磁盘满, I/O 失败等) 直接上抛, 使该条目失败.

替代方案是任一属性失败即整体失败: 语义更严格, 但在 macOS 上每次备份都会因内核附加属性失败而不可用.

### 5. mtime 只设置修改时间, 显式省略 atime

使用 `utimensat`, 将 atime 设为 `UTIME_OMIT`, mtime 取源对象的 `mtime()` / `mtime_nsec()`. 这样不会因为备份动作把 atime 改成当前时刻, 也不承诺保留 atime.

### 6. 不复制所有权与符号链接元数据

`chown` 需要特权, 且备份作为用户自己的副本更合理. 对符号链接只复制链接文本; 在 macOS/Linux 上对链接设置扩展属性既不一致也价值有限, 明确排除.

### 7. 旧备份按自身元数据恢复

不为旧备份引入标记或旁路文件. 旧备份的 mtime 是备份时刻, 恢复时就把目标 mtime 设为该值; 内容与权限仍正确. 这是相对现状 (恢复后 mtime 为当前时刻) 的更接近原状的取值, 并在文档中说明.

## Risks / Trade-offs

- [在无扩展属性支持的文件系统上静默降级] -> 这是有意选择; 在 README 与设计文档中说明"尽力而为", 不改变输出契约, 避免为警告新增第二种输出流.
- [macOS ACL 不被保留] -> 明确列为非目标; 不给出虚假承诺.
- [逐属性系统调用增加大目录备份开销] -> dotfile 规模通常很小; 每个对象多一次 `listxattr`, 每个属性多一对 `get/set`. 不对性能设门槛, 但实现不做多余重复读取.
- [元数据写入失败导致备份整体失败, 用户暂时无法覆盖] -> 原对象保持原样, 失败原因包含具体路径; 与现有"备份失败不删除原对象"的语义一致.
- [旧备份恢复后 mtime 是备份时刻] -> 文档说明; 没有可靠信息能还原更早的 mtime.
- [复制 `security.*` 等受限属性失败] -> 落入尽力而为分类, 跳过; 非特权进程不会因此中断备份.

## Migration Plan

- 纯加法: 无清单格式, CLI, 输出或退出码变化; 既有备份继续可被 `undo` 发现与恢复.
- 回滚策略: 回退实现后行为回到"内容 + 权限位", 已产生的备份仍可用.
- 文档同步: `README.md` 的备份说明与已知限制, `specs/001-dotfile-link-management/data-model.md` 第 4 节的备份内容表.
