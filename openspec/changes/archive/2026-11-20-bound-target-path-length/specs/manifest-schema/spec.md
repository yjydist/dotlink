# Spec Delta

## ADDED Requirements

### Requirement: 目标完整路径长度预算 [V-13]

`target` 的规范化绝对路径字节数 (按 UTF-8) 加上工具可能追加的最长生成后缀 MUST 不超过平台路径预算. 最长生成后缀取备份最终名, 备份暂存名, 恢复暂存名, 替换暂存名与撤销暂存名中的最大者, 当前按 55 字节预留 (覆盖 7 位 pid, 2 位序号, `.partial` 与 `.dotlink-restore.partial` 等). 平台预算取自 `<limits.h>` 的 `PATH_MAX`: Linux 4096 字节, macOS 1024 字节. 超过时整体拒绝, 退出码 2, 零改动, 说明 MUST 给出条目下标, 书写形态, 解析后字节数与预算. 相对 `target` 按仓库根解析, 所以同一清单的接受面随仓库位置变化. 本预算的常量与 V-12 的 200 字节预算放在同一共享模块.

#### Scenario: 恰好预算接受

- **WHEN** 某条目的 `target` 规范化后字节数恰为 `PATH_MAX - 55`, 例如 Linux 上 4041 字节
- **THEN** 清单被接受, 四条命令按各自语义正常执行, 不在清单阶段报告路径长度

#### Scenario: 超出预算 1 字节拒绝

- **WHEN** 某条目的 `target` 规范化后字节数为 `PATH_MAX - 55 + 1`
- **THEN** 整体拒绝, 退出码 2, 零改动, 说明包含条目下标, 书写形态, 解析后字节数与预算

#### Scenario: 多字节路径按字节计

- **WHEN** 某条目的 `target` 由 3 字节 UTF-8 字符组成, 字符数看似未超预算但字节数超过 `PATH_MAX - 55`
- **THEN** 整体拒绝, 退出码 2, 说明按字节给出解析后长度, 不按字符数或显示宽度计算

#### Scenario: 相对 target 随仓库移动可能被拒

- **WHEN** 同一份含相对 `target` 的清单在较浅的仓库根下被接受, 随后仓库被移动到更深的目录使规范化绝对路径超过预算
- **THEN** 在新位置运行任一条命令都整体拒绝, 退出码 2, 说明给出解析后的绝对路径字节数

#### Scenario: 合法短路径不受影响

- **WHEN** 清单中的 `target` 规范化后远短于预算, 例如 `~/.bashrc`
- **THEN** 清单被接受, `apply` 与 `undo` 行为与既有规格一致, 不因 V-13 改变
