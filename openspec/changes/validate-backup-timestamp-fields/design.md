# Design

## Context

见 `proposal.md` 的 Why. 现状把 "完整命名" 落在 `src/backup.rs` 的 `is_timestamp`:

- 只判断长度 15, 前 8 位 ASCII 数字, 第 9 位 `T`, 后 6 位 ASCII 数字;
- `complete_suffix_of` 用它区分 "完整备份" 与 `.partial` 残留, 再拆出 `(时间戳, 序号)` 作为排序键;
- 排序键原样保存时间戳字符串, 因此 "字典序即时间序" 只在字段合法时才成立 (非法值同样能排到最前).

`time` 已经是生产依赖 (`timestamp()` 用 `OffsetDateTime::now_utc()`), 提供
`Date::from_calendar_date` 与 `Time::from_hms` 两个返回 `Result` 的构造函数.

## Goals / Non-Goals

- Goal: "完整命名" 同时意味着 "合法的 UTC 日历时刻", 使排序前提成立.
- Goal: 校验对既有合法备份零影响, 不需要迁移.
- Non-Goal: 不校验时间戳是否在未来, 不与墙钟比较 (定时器回拨仍是 README 记录的已知限制).
- Non-Goal: 不清理, 不重命名, 不移动非法名字; 不改变命名空间划分与报告格式.

## Decisions

### D1. 用 `time` 做日历校验, 不只校验字段范围

备选一: 只判断月 1-12, 日 1-31, 时 0-23, 分秒 0-59. 否决: 仍接受 `20260230` 这类 "字段看着合理但不存在
的日期", 留下同一类问题的窄只剩 "月末" 的口子. 备选二: 手写每月天数与闰年规则. 否决: 与 `time` 已有的
日历实现重复, 且闰年规则写错时很难被发现. 备选三 (现状): 只校验形态. 已复现为缺陷.

代价: 每个候选名字多一次解析. 扫描只在 `undo` 的前置快照里发生, 每个父目录一次, 名字数量是目录规模,
开销可以忽略; 不引入缓存, 也不提前返回.

### D2. 校验点放在 `is_timestamp`

`is_timestamp` 是 "这个名字算不算完整备份" 的唯一判定, 校验放这里使 `complete_suffix_of`,
`scan_backups`, `find_latest_backup` 与报告路径全部零改动: 非法名在 `complete_suffix_of` 就返回
`None`, 与 `.partial` 残留走同一条 "不参与" 路径.

备选: 在 `cmp_backup_key` 里对非法值降权. 否决: 那会让非法名仍进入 `latest` 表, 可能成为 "唯一候选"
而被选中; "不参与" 必须是排除, 不是排序修正.

### D3. 非法名只忽略, 不清理

删除用户目录里的文件超出本命令职责, 也与 "备份不被自动回收" 冲突. 忽略足以阻断 "恢复出垃圾内容";
名字本身留在原地供用户自行判断.

## Risks / Trade-offs

- **严格校验忽略某些外部工具生成的备份名** -> 只有字段值非法的名字会被忽略, 而这类名字本来就不能保证
  是 "某个真实时刻的备份"; 忽略优于恢复来路不明的内容. README 的查找边界会写明这一点.
- **旧版本按本地时区写成的备份名** -> 它们仍是合法日历值, 校验不会拒绝, 只影响排序语义 (已记录的
  已知限制), 因此没有迁移步骤.
- **`time` 的年份范围与 4 位数字形态不完全一致** (例如年份 `0000`) -> 校验以 "能否构成合法日期" 为准;
  本工具生成的年份始终来自 `now_utc()`, 不会出现边界年份, 只需在单测里固定住当前接受范围.
- **校验逻辑分散在两处会漂移** -> 让 `is_timestamp` 成为唯一入口, 单测同时覆盖形态与字段两类反例.

## Migration Plan

无. 新旧合法备份名的判定结果相同; 只有字段非法的名字从 "参与" 变为 "不参与".
