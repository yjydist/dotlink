# Proposal

## Why

`backup-lifecycle` 要求只让 "完整命名" 的备份参与查找, 但实现把 "完整命名" 只解释成字符形态: 后缀为 15
个字符, 前 8 位数字, 第 9 位是 `T`, 后 6 位数字. 字段值从不校验, 因此一个字段非法但形态合法的名字会
参与排序, 并且因为字典序更大而被当成 "最新". 已复现:

```
~/.rc.dotlink-backup.20260101T000000   (真实备份, 内容 real-old)
~/.rc.dotlink-backup.99999999T999999   (非法时刻, 内容 bogus)
$ dotlink undo
1/1 restore  ~/ts/.rc  目标为空, 已从备份恢复: .../.rc.dotlink-backup.99999999T999999
```

结果是 "恢复" 出一份来路不明的内容, 而真正的备份被留在原地. 这类名字只会由人工或外部工具创建, 但
`undo` 把它当作本工具产物正是 "完整命名" 这条不变量的失效点.

## What Changes

- 查找时除字符形态外再校验时间戳字段: 年 4 位数字, 月 01-12, 日在该月范围内, 时 00-23, 分与秒 00-59.
  字段非法的名字不参与 "取最新", 不被撤销消费, 也不被当作 "有可用备份".
- 校验复用已有的 `time` 依赖做日历判定 (含闰日), 不新增依赖.
- 不删除, 不重命名, 不移动任何既有名字: 非法名保持原样留在磁盘上, 只是被忽略 (仍然遵守 "备份不被
  自动回收").
- 新增单元测试与端到端用例, 并在 README 的备份命名段补一句查找边界.

## Capabilities

### New Capabilities

无.

### Modified Capabilities

- `backup-lifecycle`: 新增需求 "时间戳字段非法的备份不参与查找", 补齐 "只有完整命名的备份参与查找"
  未覆盖的字段合法性.

## Impact

- `src/backup.rs`: `is_timestamp` 的判定与注释, 相应单元测试.
- `tests/undo.rs`: 端到端回归用例.
- `README.md`: 备份命名段落的查找边界.
- 不受影响: 备份生成 (仍写合法 UTC 时间戳), 排序键, 命名空间划分, 报告格式, 退出码, 依赖树.
