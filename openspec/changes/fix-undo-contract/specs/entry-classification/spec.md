# Spec Delta

## MODIFIED Requirements

### Requirement: 目标谓词对特殊状态的计数基准

导出退出码时, 部署, 预览与检查的目标谓词 MUST 把"未部署"计为"该目标尚未成为正确链接"; "源缺失"与"无法判定" MUST NOT 计入上述谓词. 后两者的残留待办已由"无遗留待办"这一独立条件表达, 若谓词也计数, 两个条件会在同一批条目上重复生效. 撤销的目标谓词刻意相反 (要求目标路径上不存在本工具创建的链接, 且本次没有从备份恢复内容), 对"未部署且无备份可恢复"的取值为真; 目标为空但有备份可恢复时为假, 因为 `restore` 是本次撤销的实际动作, 不适用本条的计数基准.

#### Scenario: 只含源缺失的清单上撤销

- **WHEN** 清单的唯一条目源缺失, 执行撤销
- **THEN** 目标谓词不因该条目为假, 但退出码仍为 1, 因为它计入"失败"列

#### Scenario: 只含源缺失的清单上预览

- **WHEN** 清单的唯一条目源缺失, 执行预览
- **THEN** 目标谓词不因该条目为假, 但退出码仍为 1, 因为它计入"失败"列

#### Scenario: 未部署使部署谓词为假

- **WHEN** 清单的唯一条目未部署, 执行预览
- **THEN** 目标谓词为假, 退出码 1

#### Scenario: 未部署且有备份使撤销谓词为假

- **WHEN** 清单的唯一条目目标为空, 同目录有一份完整备份, 执行撤销
- **THEN** 目标谓词为假, token 为 `restore`, 退出码 1

#### Scenario: 源缺失且目标为空但有备份

- **WHEN** 清单的唯一条目源缺失, 目标为空, 同目录有一份完整备份, 执行撤销
- **THEN** token 为 `missing`, 备份不被恢复, 目标保持为空, 退出码 1
