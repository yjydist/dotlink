# Spec Delta

## ADDED Requirements

### Requirement: 空目标恢复的退出码与源缺失边界

目标路径本就不存在且同目录有一份完整命名的用户备份时, `undo` MUST 恢复该备份, token 为 `restore`, 计入成功列, 但退出码 MUST 为 1: 本次撤销实际执行了恢复动作, 不满足"没有从备份恢复任何内容"的目标谓词. 该恢复 MUST NOT 先移除任何对象, MUST 在落位时拒绝覆盖期间新建的内容, 且 MUST NOT 消费备份.

源路径缺失时, `undo` MUST 报告 `missing` 并计入失败列; 即使目标为空且同目录有完整备份, MUST NOT 恢复该备份. 源缺失优先于目标侧事实, 因为无法建立有意义的一致性; 用户需要先恢复源条目, 或手工处理备份.

#### Scenario: 目标为空且有备份的退出码

- **WHEN** 目标路径本就不存在, 同目录有一份完整备份, 执行 `undo`
- **THEN** 备份被恢复到目标, token 为 `restore`, 汇总计入成功列, 退出码 1, 备份仍在原地

#### Scenario: 源缺失时不恢复空目标上的备份

- **WHEN** 源路径不存在, 目标路径为空, 同目录有一份完整备份, 执行 `undo`
- **THEN** token 为 `missing`, 目标仍为空, 备份未被恢复或删除, 退出码 1

#### Scenario: 源缺失时不恢复悬空链接

- **WHEN** 源路径不存在, 目标路径上仍是指向该源的旧链接, 同目录有一份完整备份, 执行 `undo`
- **THEN** token 为 `missing`, 链接保持原样, 备份未被恢复或删除, 退出码 1
