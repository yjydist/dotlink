# Proposal

## Why

V-5, V-9, V-10 与 V-11 的路径判定只比较 `os::normalize` 后的路径字符串. macOS 默认 APFS 大小写不敏感, 且存在 firmlink 别名 (`/Users/...` 与 `/System/Volumes/Data/Users/...`), 同一文件或目录可以有多种写法. 实测: 把 `target` 写成仓库根或清单文件的大小写别名后, 四类校验全部放行, `apply` 会先备份再删除整份仓库或替换清单文件; `source = "a"` 配 `target = "A"` 通过 V-10 后会在原路径建出自指链接, 源内容只剩备份. 校验规则原本要保护的落点 (文件系统根, 主目录, 仓库根, 唯一配置源) 在受支持的主要平台上可被别名写法绕过.

## What Changes

- 新增只读的文件系统身份判等: 对已存在的基准点 (文件系统根, 主目录的书写形态与物理形态, 仓库根及其祖先, 清单文件) 记录 `(st_dev, st_ino)`. `target` 落点存在且与任一基准同身份时, 视为命中该退化落点并整体拒绝.
- V-5 目标唯一: 两个 `target` 都存在且身份相同时视为重复声明, 即使书写形态不同.
- V-10 自指: `target` 与 `source` 都存在且身份相同时视为自指.
- V-11 路径隔离: 两侧都存在时, 同一身份视为同一路径; 判断包含关系时, 用目标与源的祖先身份与对侧身份集合比较, 覆盖别名形态的嵌套.
- 身份判等是**单调收紧**: 只增加拒绝条件, 不把原本拒绝的清单改为接受; 路径不存在或身份读取失败时退回现有字符串比较, 不新增清单错误.
- **BREAKING**: 之前能通过校验的别名形态清单现在整体拒绝, 退出码 2, 零改动.
- 新增平台门控测试: 大小写不敏感卷上断言别名被拒; macOS 上探测 firmlink 别名; 卷大小写敏感时跳过别名用例. README 的 V-9 说明与已知限制补充别名语义.

## Capabilities

### New Capabilities

无.

### Modified Capabilities

- `manifest-schema`: V-5, V-9, V-10, V-11 增加文件系统身份判等, 别名写法的退化落点, 重复目标与自指同样被拒.

## Impact

- 代码: `src/manifest.rs` (校验流程与身份集合), `src/os/mod.rs` (身份原语); 不改 `classify`, `apply`, `undo` 的判定语义.
- 测试: `tests/manifest_errors.rs` 增加大小写别名与 firmlink 用例; `src/manifest.rs` 与 `src/os/mod.rs` 增加单测; 卷能力探测辅助放在测试夹具中.
- 文档: `README.md` 的 V-9 段落与"已知限制" (清单文件为符号链接的残余风险会被身份判等顺带关闭, 需同步措辞).
- 兼容性: 只影响清单校验; 报告格式, token, 退出码语义与备份格式不变. 身份探测为只读 `stat`, 不改变"校验先于任何文件系统改动"的性质.
- 依赖与平台: 不新增依赖; 身份判等使用 `std` 元数据, macOS 与 Linux 行为一致.
