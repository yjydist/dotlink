# Spec Delta

## MODIFIED Requirements

### Requirement: 清单校验 V-5: 目标路径唯一

系统 MUST 在规范化之后比较目标路径: 不存在两个条目声明同一个目标路径. 书写形态不同但规范化结果相同时同样拒绝, 说明 MUST 指出冲突的两个条目下标. 比较 MUST NOT 使用 `Path::canonicalize` -- 待部署的目标通常尚不存在. 两个目标路径都存在时, 判重 MUST 同时比较文件系统身份 (设备号与 inode): 不同写法指向同一对象时同样视为同一目标路径.

#### Scenario: 两种写法指向同一目标

- **WHEN** 两个条目分别写 `~/.bashrc` 与 `~/./.bashrc`
- **THEN** 整体拒绝, 退出码 2, 说明指出这两个条目

#### Scenario: 同一源配不同目标

- **WHEN** 两个条目使用同一个 `source`, 但 `target` 不同且互不包含
- **THEN** 清单被接受

#### Scenario: 大小写别名指向同一目标

- **WHEN** 在大小写不敏感的文件系统上, 两个条目分别把 `target` 写成既有文件 `~/.bashrc` 与 `~/.BASHRC`
- **THEN** 整体拒绝, 退出码 2, 说明指出这两个条目, 而不是让两条目先后操作同一个对象

### Requirement: 清单校验 V-9: 目标落点不得退化

`target` 规范化后命中文件系统根 `/`, 当前用户主目录, 仓库根本身或其祖先 (如 `.` / `..`), 或清单文件自身 (仓库根下的 `dotlink.toml`) 时 MUST 整体拒绝, 说明 MUST 指出条目下标与书写形态. 这些落点一旦被替换备份, 毁掉的是整个文件系统, 整个主目录或源仓库; 替换清单文件自身会让后续命令失去唯一配置源. `~/sub` 与 `/etc/hosts` 这类合法落点不受影响. 主目录比较以 `HOME` 可解析为前提: `HOME` 缺失, 空值或为相对路径时无法确定主目录, 该项比较不适用, 清单 MUST NOT 因 `HOME` 不可用而被拒绝 (与"主目录解析"一致). 主目录的判别 MUST 同时覆盖 `HOME` 的书写形态与其解析末尾符号链接后的物理形态: `HOME` 自身可能是符号链接, 只比较其中一种形态会让写在另一种形态下的主目录落点漏过. 目标落点存在时, 命中判定 MUST 同时比较文件系统身份 (设备号与 inode): 与任一基准点指向同一对象的其它写法 (大小写别名, firmlink 别名) 同样命中. 身份读取不可用 (路径不存在或元数据读取失败) 时 MUST 退回规范化字符串比较, MUST NOT 因此拒绝清单.

#### Scenario: 裸 ~ 作为落点

- **WHEN** 某条目写 `target = "~"`
- **THEN** 整体拒绝, 退出码 2, 说明指出不能以主目录本身为落点

#### Scenario: 主目录路径本身是符号链接

- **WHEN** `HOME` 本身是一个符号链接, 而某条目把 `target` 写成该主目录解析符号链接后的物理路径
- **THEN** 整体拒绝, 退出码 2, 说明指出不能以主目录本身为落点

#### Scenario: 仓库根作为落点

- **WHEN** 某条目写 `target = "."` 或 `target = "sub/../.."`
- **THEN** 整体拒绝, 说明指出不能以源仓库为落点

#### Scenario: 清单文件自身作为落点

- **WHEN** 某条目写 `target = "dotlink.toml"` 或等价的绝对路径
- **THEN** 整体拒绝, 退出码 2, 说明指出不能以清单文件自身为落点

#### Scenario: 大小写别名形式的仓库根

- **WHEN** 在大小写不敏感的文件系统上, 某条目把 `target` 写成仓库根路径的大小写变体
- **THEN** 整体拒绝, 退出码 2, 说明指出不能以源仓库为落点, 而不是当作普通目录备份后替换

#### Scenario: 别名形式的清单文件

- **WHEN** 某条目把 `target` 写成清单文件路径的另一种写法 (大小写变体或等价别名)
- **THEN** 整体拒绝, 退出码 2, 说明指出不能以清单文件自身为落点

#### Scenario: firmlink 别名形式的主目录

- **WHEN** 在 macOS 上, 某条目把 `target` 写成主目录的 firmlink 别名路径 (如 `/System/Volumes/Data/Users/<用户>`)
- **THEN** 整体拒绝, 退出码 2, 说明指出不能以主目录本身为落点

#### Scenario: 不存在的落点只做字符串比较

- **WHEN** 某条目的 `target` 不存在, 且其规范化字符串不等于任何基准路径
- **THEN** 清单被接受, 身份判等不可用不会使校验失败

### Requirement: 清单校验 V-10: 目标不得自指

`target` 规范化后 MUST NOT 与本条目自己的 `source` 相同: 自指链接无法解析为一个存在的目标, 且 `replace_and_backup` 会先备份源文件, 再在原路径建立指向该路径自身的链接 (符号链接环), 使原路径不可用. 违反时说明 MUST 指出条目下标与书写形态. `target` 与 `source` 都存在时, 判等 MUST 同时比较文件系统身份 (设备号与 inode): 指向同一对象的两种写法同样视为自指.

#### Scenario: 两种写法归一化后重合

- **WHEN** 某条目写 `source = "shell/bashrc"` 与 `target = "shell/../shell/bashrc"`
- **THEN** 整体拒绝, 退出码 2, 说明指出自指

#### Scenario: 大小写别名形式的自指

- **WHEN** 在大小写不敏感的文件系统上, 某条目写 `source = "a"` 与 `target = "A"`, 两者是同一个文件
- **THEN** 整体拒绝, 退出码 2, 说明指出自指, 而不是备份源文件后建出自指链接

### Requirement: 清单校验 V-11: 源与目标路径隔离

目标之间 MUST NOT 互为祖先或后代; 任一目标 MUST NOT 与任一源路径相同, 包含或被包含. 比较以规范化后的路径组件为准, 多个独立目标仍可共享同一源. 违反时四条命令都在改动前拒绝. 参与比较的路径存在时, 判等与包含判定 MUST 同时比较文件系统身份 (设备号与 inode): 目标与源的祖先身份相同, 或与对侧路径身份相同, 均视为重叠.

#### Scenario: 目录目标下的子目标

- **WHEN** 一条部署整个目录, 另一条把目标写在该目录内部
- **THEN** 整体拒绝, 退出码 2, 说明指出相关条目与路径, 因为通过父链接可以修改源目录

#### Scenario: 目标覆盖另一条目的源

- **WHEN** 条目 A 的 `target` 等于条目 B 的 `source`
- **THEN** 整体拒绝, 退出码 2, 说明指出两个条目与重叠路径

#### Scenario: 目标包含本条目的源

- **WHEN** 某条目写 `source = "shell/bashrc"` 与 `target = "shell"`
- **THEN** 整体拒绝, 退出码 2, 说明指出该条目与重叠路径

#### Scenario: 别名形式的目录嵌套

- **WHEN** 一条部署整个仓库目录的别名写法, 另一条把目标写在仓库内部的子路径, 两条路径在文件系统上是同一个目录
- **THEN** 整体拒绝, 退出码 2, 说明指出相关条目与路径, 而不是放行后再通过父链接改写源目录
