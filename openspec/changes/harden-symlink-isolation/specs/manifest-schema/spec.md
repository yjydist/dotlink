# Spec Delta

## MODIFIED Requirements

### Requirement: 清单校验 V-5: 目标路径唯一

系统 MUST 在规范化之后比较目标路径: 不存在两个条目声明同一个目标路径. 书写形态不同但规范化结果相同时同样拒绝, 说明 MUST 指出冲突的两个条目下标. 比较 MUST NOT 使用 `Path::canonicalize` -- 待部署的目标通常尚不存在. 两个目标路径都存在时, 判重 MUST 同时比较文件系统身份 (设备号与 inode): 不同写法指向同一对象时同样视为同一目标路径. 比较 MUST 同时使用词法规范化形态与解析末段符号链接后的比较形态; 两种形态任一重合 MUST 视为同一目标.

#### Scenario: 两种写法指向同一目标

- **WHEN** 两个条目分别写 `~/.bashrc` 与 `~/./.bashrc`
- **THEN** 整体拒绝, 退出码 2, 说明指出这两个条目

#### Scenario: 同一源配不同目标

- **WHEN** 两个条目使用同一个 `source`, 但 `target` 不同且互不包含
- **THEN** 清单被接受

#### Scenario: 大小写别名指向同一目标

- **WHEN** 在大小写不敏感的文件系统上, 两个条目分别把 `target` 写成既有文件 `~/.bashrc` 与 `~/.BASHRC`
- **THEN** 整体拒绝, 退出码 2, 说明指出这两个条目, 而不是让两条目先后操作同一个对象

#### Scenario: 符号链接目标与其 referent 同时出现

- **WHEN** 第一个条目的 `target` 是符号链接 `~/.config`, 第二个条目的 `target` 写成该链接解析后的同一目录
- **THEN** 整体拒绝, 退出码 2, 说明指出两个条目, 而不是把同一对象当成两个独立目标

### Requirement: 清单校验 V-9b: 落点命中按文件系统身份判定

目标落点存在时, 命中判定 MUST 同时比较文件系统身份 (设备号与 inode): 与任一基准点指向同一对象的其它写法 (大小写别名, firmlink 别名) 同样命中. 身份读取不可用 (路径不存在或元数据读取失败) 时 MUST 退回规范化字符串比较, MUST NOT 因此拒绝清单. 基准点的身份 MUST 同时保存 lstat 形态与 follow 形态; 落点的 lstat 身份命中任一形态 MUST 视为同一对象.

#### Scenario: 大小写别名形式的仓库根

- **WHEN** 在大小写不敏感的文件系统上, 某条目把 `target` 写成仓库根路径的大小写变体
- **THEN** 整体拒绝, 退出码 2, 说明指出不能以源仓库为落点, 而不是当作普通目录备份后替换

#### Scenario: 别名形式的清单文件

- **WHEN** 某条目把 `target` 写成清单文件路径的另一种写法 (大小写变体或等价别名)
- **THEN** 整体拒绝, 退出码 2, 说明指出不能以清单文件自身为落点

#### Scenario: firmlink 别名形式的主目录

- **WHEN** 在 macOS 上, 某条目把 `target` 写成主目录的 firmlink 别名路径 (如 `/System/Volumes/Data/Users/<用户>`)
- **THEN** 整体拒绝, 退出码 2, 说明指出不能以主目录本身为落点

#### Scenario: 不存在的落点只做字符串比较

- **WHEN** 某条目的 `target` 不存在, 且其规范化字符串不等于任何基准路径
- **THEN** 清单被接受, 身份判等不可用不会使校验失败

#### Scenario: 主目录符号链接的 lstat 形态

- **WHEN** `HOME` 本身是符号链接, 某条目把 `target` 写成该符号链接路径的大小写变体或等价别名
- **THEN** 整体拒绝, 退出码 2, 说明指出不能以主目录本身为落点, 而不是因为 lstat 与 follow 身份不同而放行

### Requirement: 清单校验 V-10: 目标不得自指

`target` 规范化后 MUST NOT 与本条目自己的 `source` 相同: 自指链接无法解析为一个存在的目标, 且 `replace_and_backup` 会先备份源文件, 再在原路径建立指向该路径自身的链接 (符号链接环), 使原路径不可用. 违反时说明 MUST 指出条目下标与书写形态. `target` 与 `source` 都存在时, 判等 MUST 同时比较文件系统身份 (设备号与 inode): 指向同一对象的两种写法同样视为自指. `source` 是符号链接时, 判等 MUST 同时比较 source 的 follow 身份与链接文本的解析目标; `target` 命中任一形态 MUST 视为自指.

#### Scenario: 两种写法归一化后重合

- **WHEN** 某条目写 `source = "shell/bashrc"` 与 `target = "shell/../shell/bashrc"`
- **THEN** 整体拒绝, 退出码 2, 说明指出自指

#### Scenario: 大小写别名形式的自指

- **WHEN** 在大小写不敏感的文件系统上, 某条目写 `source = "a"` 与 `target = "A"`, 两者是同一个文件
- **THEN** 整体拒绝, 退出码 2, 说明指出自指, 而不是备份源文件后建出自指链接

#### Scenario: 源符号链接指向目标

- **WHEN** 仓库内的 `source` 是一个符号链接, 其链接文本解析后等于该条目的 `target`, 或 `target` 位于其解析目标之内
- **THEN** 整体拒绝, 退出码 2, 说明指出源符号链接的解析目标与目标重叠, 而不是建立 `target -> source -> target` 的环

### Requirement: 清单校验 V-11: 源与目标路径隔离

目标之间 MUST NOT 互为祖先或后代; 任一目标 MUST NOT 与任一源路径相同, 包含或被包含. 比较以规范化后的路径组件为准, 多个独立目标仍可共享同一源. 违反时四条命令都在改动前拒绝. 参与比较的路径存在时, 判等与包含判定 MUST 同时比较文件系统身份 (设备号与 inode): 目标与源的祖先身份相同, 或与对侧路径身份相同, 均视为重叠. 比较 MUST 同时使用词法规范化形态与解析末段符号链接后的比较形态; 两种形态任一构成祖先/后代或身份重叠 MUST 视为重叠. `source` 是符号链接时, 其 follow 身份与链接文本的解析目标 MUST 同时参与比较.

#### Scenario: 目录目标下的子目标

- **WHEN** 一条部署整个目录, 另一条把目标写在该目录内部
- **THEN** 整体拒绝, 退出码 2, 说明指出相关条目与路径, 因为通过父链接可以修改源目录

#### Scenario: 目标覆盖另一条目的源

- **WHEN** 条目 A 的 `target` 等于条目 B 的 `source`
- **THEN** 整体拒绝, 退出码 2, 说明指出两个条目与重叠路径

#### Scenario: 目标包含本条目的源

- **WHEN** 某条目写 `source = "shell/bashrc"` 与 `target = "shell"`
- **THEN** 整体拒绝, 退出码 2, 说明指出该条目与重叠路径

#### Scenario: 别名形式的目录嵌套

- **WHEN** 一条部署整个仓库目录的别名写法, 另一条把目标写在仓库内部的子路径, 两条路径在文件系统上是同一个目录
- **THEN** 整体拒绝, 退出码 2, 说明指出相关条目与路径, 而不是放行后再通过父链接改写源目录

#### Scenario: 符号链接父目标下的子目标

- **WHEN** 第一个条目的 `target` 是符号链接 `~/.config`, 第二个条目的 `target` 是 `~/.config/nvim/init.lua`
- **THEN** 整体拒绝, 退出码 2, 零改动, 说明指出两个条目与命中的比较路径

#### Scenario: 源符号链接指向目标祖先

- **WHEN** 某条目的 `source` 是符号链接, 其解析目标包含另一个条目的 `target`, 或等于目标
- **THEN** 整体拒绝, 退出码 2, 零改动, 说明指出源符号链接的解析目标与目标重叠
