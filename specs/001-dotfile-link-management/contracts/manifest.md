# 契约: 清单文件格式 (`dotlink.toml`)

**契约类型**: 用户编写的输入格式.一旦发布, 已存在的清单必须继续可用; 破坏性调整需按 `BREAKING CHANGE` 处理.

**定位规则**: 清单固定命名为 `dotlink.toml`, 从**当前工作目录**查找, 不向上搜索父目录.找不到即为校验失败 (退出码 2).

**当前工作目录不可用**: 与"找不到清单"同为校验失败 (退出码 2), 但说明必须可区分 -- 目录被删除时进程甚至无法确定自己在哪, 报"找不到 `dotlink.toml`"会把用户引向错误的方向. 两种情况与"子命令拼错"三者都用码 2, 区分方式一律由标准错误的文字承担 (见 `contracts/cli.md` 的"调用方式错误").

**仓库根目录**: 清单文件所在目录.所有源条目相对路径以它为基准解析.源条目解析并归一化后必须仍落在它之内 —— `..` 段或仓库内的符号链接把 `source` 带出仓库时整份清单被拒绝 (退出码 2, 指出条目下标与书写形态, 零改动): 越出仓库的链接文本会让 `undo` 的归属判定 (落在仓库内才算本工具创建) 拒删本工具自己的产物.没有 `--repo` 参数 —— 仓库根由清单位置唯一确定, 避免出现与清单位置矛盾的第二个来源.

---

## 格式

```toml
# 可选: 顶层无其他键. 条目以 [[entry]] 数组表给出.
# 至少需要一个条目.

[[entry]]
source = "bash/bashrc"          # 必填: 仓库内的相对路径, 文件或目录
target = "~/.bashrc"            # 必填: 目标路径, 支持 ~ 与相对路径

[[entry]]
source = "nvim"
target = "~/.config/nvim"

[[entry]]
source = "git/gitconfig"
target = "~/.gitconfig"
on_conflict = "replace_and_backup"          # 可选: "skip" (默认) | "replace_and_backup"
```

## 字段

| 键 | 必填 | 取值 | 默认 | 语义 |
|----|------|------|------|------|
| `source` | 是 | 非空字符串 | — | 仓库内相对路径 (不接受 `~` 前缀、绝对路径, 以及解析后落在仓库之外的路径).允许文件与目录 |
| `target` | 是 | 非空字符串 | — | 目标路径.规则见下 |
| `on_conflict` | 否 | `"skip"` \| `"replace_and_backup"` | `"skip"` | 目标被非本工具内容占用时的策略 |

未知键的处理: 出现未定义的键时**拒绝整份清单** (退出码 2) 并指出键名.理由: 这是最可能的用户错误 (拼错 `on_conflict` 会静默变成默认 `skip`, 让用户以为配置生效了却没生效), 静默忽略比报错危险得多.

该规则**同时适用于两个层级**, 两层都只有各自的合法键:

| 层级 | 合法键 |
|------|--------|
| 顶层 (文档根) | 仅 `entry` |
| 每个 `[[entry]]` 表 | 仅 `source` / `target` / `on_conflict` |

因此顶层的 `[foo]` 与条目内的 `sorce = "..."` (拼错 `source`) 都是整体拒绝. 本规则在 `data-model.md` 第 1 节记为 **V-8**, 与 V-1 到 V-7 同为"清单自身的缺陷".

## `target` 解析规则

| 形态 | 解析为 |
|------|--------|
| `~/...` 或裸 `~` | 展开为当前用户主目录 (`HOME`); `~/x` → 主目录下的 `x` |
| 其他以 `~` 开头的形态 | **拒绝** (V-6): 主目录简写只支持 `~` 与 `~/...` |
| 绝对路径 | 原样使用 |
| 相对路径 | 相对于清单文件所在目录 (仓库根) |

"其他以 `~` 开头的形态" 指 `~.bashrc` (漏写斜杠的常见笔误) 与 `~foo/bar` (指其他用户的主目录) 之类. 它们既不是本工具支持的主目录简写, 也不是绝对路径, 若放行会落进"相对路径"分支, 在**仓库内**静默建出名为 `~.bashrc` 的路径并报告成功 -- 而落点恰是受版本控制的 dotfile 仓库. 与未知键的处理同理 (拼错的形态静默退化比报错危险得多), 一律整体拒绝并指出条目下标与非法形态, 退出码 2.

主目录无法确定时 (无 `HOME`) 属于校验失败 (退出码 2).

解析后进行规范化再使用, 见 `research.md` R2 与 R5.规范化用于**比较与归属判定**; 报告中展示的是用户书写的原始字符串, 便于用户对照自己的清单.

**落点不得退化**: `target` 归一化后命中文件系统根 `/`、当前用户主目录 (裸 `~` 或书成绝对路径的等价形态)、仓库根本身或其祖先 (如 `.` / `..`)、或该条目自己的 `source` 时, 整份清单被拒绝 (退出码 2, 指出条目下标与书写形态, 零改动), 见校验一节的 V-9 / V-10.这些落点一旦被替换备份, 毁掉的是整个目录、整个主目录乃至源仓库. `~/sub`、`/etc/hosts` 这类绝对路径与相对仓库根的 `target` 不受影响.

## 校验

校验在**任何文件系统改动之前**完成, 规则见 `data-model.md` 第 1 节 V-1 到 V-7 (V-8 见上文"未知键的处理").任一条不满足 → 退出码 2, 零改动.

其后新增的两条落点校验同为整体拒绝 (退出码 2, 指出条目下标与书写形态, 零改动):

| 规则 | `target` 归一化后命中即拒绝 | 理由 |
|------|------------------------------|------|
| V-9 | 文件系统根 `/` | 落点波及整个文件系统 |
| V-9 | 当前用户主目录 (裸 `~` 或等价的绝对路径) | 被替换备份的是主目录本身 |
| V-9 | 仓库根本身或其祖先 (如 `.` / `..`) | `replace_and_backup` 会毁掉源仓库 |
| V-10 | 本条目自己的 `source` 路径 | 自指链接恒为断链 |

**不校验**: 源条目在仓库中是否存在.它由条目的运行时状态 `SourceMissing` 表达, 只影响该条目, 不阻塞其余条目.

## 相对目标路径 (清单样例之外的合法形态)

上面三个样例的 `target` 全都是 `~` 开通的形式.本节的相对路径形态同样合法且必须实现 (`data-model.md` 的 V-6 要求每个 `target` 可解析为绝对路径, 含相对路径可挂到仓库根这一分支):

```toml
[[entry]]
source = "shell/bashrc"
target = "link/bashrc"    # 相对于清单文件所在目录, 即仓库根
```

**边界 (自指清单)**: 相对 `target` 挂到仓库根后若与**本条目**的 `source` 归一化到同一路径 (例如上面把 `target` 写作 `shell/bashrc`), 整份清单被拒绝 (退出码 2, 指出条目下标与书写形态, 零改动) -- 自指链接恒为断链, 而 `replace_and_backup` 还会把源文件本身备份后再替换成指向备份的链接, 破坏该条目的后续判定. 这是校验一节的 V-10. **跨条目**的重合 (条目甲的 `target` 恰是条目乙的 `source`) 不属自指, 不做校验, 由判定阶段的状态暴露.

## 示例: 完整可运行的清单

```toml
[[entry]]
source = "shell/bashrc"
target = "~/.bashrc"

[[entry]]
source = "shell/zshrc"
target = "~/.zshrc"

[[entry]]
source = "nvim"
target = "~/.config/nvim"

[[entry]]
source = "git/gitconfig"
target = "~/.gitconfig"
on_conflict = "replace_and_backup"
```
